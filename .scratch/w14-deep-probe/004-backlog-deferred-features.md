## 1. SSE 实时消息推送（观察项升级）

- 现状：前端轮询已工作（消息中心/未读数），后端无 SSE 端点。
- 范围：后端 SSE 端点（EventSourceResponse + 连接管理 + 断线重连语义）、
  前端 EventSource 接入并保留轮询降级。
- 风险：与现有 token 认证集成（EventSource 不带 header → query token 或
  cookie 方案需拍板）；PyInstaller 单进程多连接的线程开销。
- 前置：产品确认推送事件集合（新消息/审批结果/订阅生成？）。

## 2. Decimal 全链路化（Pydantic 层）

- 现状：金额在应用层 quantize_money（§5 风险已声明），Pydantic 层仍是 float。
- 范围：全部金额 schema 字段 float→Decimal（condecimal），涉及
  funds/projects/budgets 等 ~10 个 schema 文件与其序列化断言。
- 风险：高——JSON 序列化行为变化波及前端契约与全部既有测试断言；
  SQLite 存取精度语义需逐一验证。
- 前置：需要专门的回归轮次（建议单独一个 w 波次），不适合夹带。

## 3. 备份审批流

- 现状：备份/恢复仅管理员权限，无审批链。
- 范围：审批任务 entity_type 扩展 + 恢复操作挂审批 + 前端审批中心适配。
- 风险：中——审批状态机是审计敏感面，回归成本高。
- 前置：产品确认哪些操作需要审批（恢复/purge/整库还原）。

## 4. 数据归档导出

- 现状：auto_package_job（按月自动打包）+ data-packages 手动导出已覆盖主场景。
- 范围（若立项）：按年度归档 + 归档清单页 + 归档数据只读回看。
- 风险：低-中。与 003 订阅生成的落盘/通知基础设施可复用。
- 前置：产品确认归档对象（村庄年度板块快照？全库？）。
