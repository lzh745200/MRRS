## 二、逐项根因与落实

### A. 告警：`There is no current event loop`（DeprecationWarning）

- **位置**：`tests/unit/test_subscription_dispatch_coverage.py::TestRunSchedulerJob::test_async_job_executes_in_fresh_loop`
- **根因**：测试用 `asyncio.get_event_loop()` 探测事件循环；被测函数 `_run_scheduler_job()` 执行后 `loop.close()` 已解绑当前 loop，此时 `get_event_loop()` 在无运行 loop 下发出 Python 3.10+ 弃用告警。
- **落实**：改为 `asyncio.get_running_loop()`（无运行 loop 时抛 `RuntimeError`，不产生告警），并以 `try/except RuntimeError` 保持原断言意图。
- **验证**：`pytest tests/unit/test_subscription_dispatch_coverage.py -W "error::DeprecationWarning"` → **14 passed**（告警被提升为错误仍全过，证明已消除）。

### B. 2 个失败用例：`traceback.py:566 UnicodeDecodeError`

- **现象**：`--tb=line` 渲染异常时抛
  `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe7 in position 34`。
- **根因（已铁证）**：**本地解释器 Python 3.11.0 的 `traceback._byte_offset_to_character_offset` 缺陷**（3.11.1 修复）。该函数对含非 ASCII 的源码行按 UTF-8 字节偏移切片再解码，偏移落在多字节字符中间即抛异常。
  - 直接实验（同一中文串 `获取用户实际权限失败`，遍历 31 个偏移）：
    - **Python 3.11.0：20/31 抛 UnicodeDecodeError**（含 `byte 0xe7`，与 v4 日志完全一致）
    - **Python 3.11.9：0/31 抛异常**
  - 触发链：测试走 `except` 分支 → `logger.error(..., exc_info=True)` 渲染含中文的异常 traceback → 命中缺陷。受害者分别是
    `app/services/database_health_service.py:191`、`app/api/v1/machine_code.py:1120`。
- **落实**：**不属本仓代码缺陷，不做“日志降级”式掩盖**。真正的根因是解释器版本过旧。
- **验证**：
  - v5（`.venv` Python 3.11.0、单进程、当前工作树）加临时探针包装该函数并复现写入 `_anchorfail.txt` → **全程无触发**，即该失败不再出现；
  - CI 门禁 `pr-checks.yml` 使用 `python-version: '3.11'`（setup-python 安装**最新 3.11.x**）+ `ubuntu-latest`，**不存在此缺陷**，且带 `--reruns 2` 兜底。

### C. 覆盖率缺口（v4 872 miss → 97.67%）

- **根因**：v4 采集时 `collected 10719 / 521 文件`，而当前工作树为 `534 文件`；差异的 **13 个测试文件**（`test_excel_report_style_cov.py`、`test_cov_gap_fill_r23.py`、`test_security_audit_exemptions.py` 等）**在 v4 运行时尚未创建**，故对应模块 `excel_report_style.py` / `pdf_report_style.py` 呈 0%。
- **落实**：这些测试文件已由同日工作流落地并提交（`git status` 中工作树仅 1 个修改文件，其余均为 HEAD 内容）。
- **验证**：v5 覆盖率由 **97.67% 提升至 99.17%**（37589 行 / 312 miss），`excel_report_style.py`、`pdf_report_style.py` 均达 **100%**。

### D. 新增 2 个真实失败（v5 暴露，**隔离可复现**）

1. **`tests/unit/test_cov_final_system_admin.py::TestRevokeUserSession::test_commit_failure_500`**
   - 现象：`Expected 'rollback' to have been called once. Called 2 times.`
   - 根因：`app/api/v1/system/admin.py` 的 `except` 块调用 `db.rollback()`，而 `safe_commit()`
     （`app/core/transaction.py:286-289`）**在 commit 失败时已自动 rollback 并重新抛出**，形成**重复回滚**（session 幂等无害，但职责重叠）。
   - 落实：**移除 `admin.py` 中冗余的 `db.rollback()`**，由 `safe_commit` 单一承载回滚职责。
   - 验证：`test_cov_final_system_admin.py` 4 passed；admin 相关 4 文件回归 **72 passed**。

2. **`tests/unit/test_cov_final_funds.py::TestTransitionStatus::test_unknown_kwarg_field_is_skipped_with_warning`**
   - 现象：`Expected 'safe_commit' to be called once. Called 2 times.`
   - 根因：`app/api/v1/funds.py::_transition_status()` **按 T048 设计分两次提交**
     （① 状态流转 + 历史日志；② 操作日志，其 `except` 注释明确「日志失败不阻断主流程」）。
     测试（2026-08-01）断言 `assert_called_once_with(db)` 系**实现演进后未同步的过时断言**。
   - 落实：**修正测试断言**为 `call_count == 2` + `assert_any_call(db)`，不改动业务行为。
   - 验证：`test_cov_final_funds.py` 11 passed。
