# 备份管理操作说明 v1.18.38（v1.18.38 复核）

## 一、自动备份（推荐保持开启）

- **默认策略**：每日凌晨 02:00 自动备份，保留最近 7 天，超出自动清理。
- **默认包含附件**：自动备份与导入/删除前的即时备份都会打包 `uploads`，避免“库回退了、附件还是新的”造成附件错挂。
  超大附件部署可在环境变量中设 `AUTO_BACKUP_INCLUDE_UPLOADS=false` 关闭（关闭后恢复时会提示需人工核对附件）。
- 配置入口：**系统管理 → 备份与存储 → 备份** →「备份计划」卡。修改后立即生效并持久化到系统配置。
- 页面会显示下次执行时间与保留策略；UI 所见即调度器真实行为。
- 单机场景建议：插一块常驻移动硬盘并在"备份目标"中选择它；仅本盘备份存在磁盘故障风险。

## 二、手动备份

1. 备份管理页点「立即备份」。
2. 可选项：
   - 加密密码（AES）：为备份包设置密码，恢复时必须提供；
   - 包含上传文件：勾选后附件一并打包；
   - 目标目录：默认写入 backups/，可选 U 盘/移动硬盘路径（页面会列出可用盘符）。
3. 磁盘剩余空间不足 500MB 时备份被拒绝并提示。

## 三、从备份恢复

⚠️ 恢复将**覆盖当前全部数据**，请先做一次当前状态的手动备份。

1. 列表中目标备份行点「恢复」→ 输入管理员密码确认。
2. 加密备份需填写创建时的密码（留空则尝试运行时密钥兜底）。
3. 恢复成功后系统跳转登录页，使用恢复库中的账号重新登录。
4. 恢复链路会自动把备份库升级到当前版本的数据库结构（失败会回滚到恢复前的快照）；若备份未包含 `uploads`，页面会提示“附件需人工核对”。

## 四、导入外部备份包（upload-restore）

1. 点「导入备份包」选择 .zip（或加密的 .rrs）。
2. 加密包必须填密码；普通 zip 必须包含数据库文件：新版为 `data/rural_revitalization.db`，
   历史备份也兼容 `data/assistance.db`、`data/assistance_management.db`、根目录同名库或 data 下唯一 .db。
   找不到数据库文件的包会被判为无效，不再“空验证通过”。
3. 上传采用分块流式处理（支持数 GB 大包），校验失败自动清理临时文件。

## 五、U 盘备份要点

- 系统自动识别可移动磁盘并列出容量；点击磁盘标签快速回填目标路径。
- NTFS/exFAT 均可；FAT32 单文件 4GB 上限，大库请先格式化为 exFAT。
- 拔盘前确认备份任务已完成（列表状态为成功且时间戳最新）。

## 六、与消息中心联动

- 每次自动备份结果（成功/失败）推送站内消息（类型=备份提醒）。
- 失败消息点击直达备份管理页排查。

## 七、每日轻量数据库维护

- 系统每日 **03:10** 在线程池中执行一次轻量维护：`PRAGMA optimize`（优化查询计划）、
  `PRAGMA wal_checkpoint(TRUNCATE)`（截断 WAL）、`PRAGMA integrity_check`（完整性自检）。
- 该维护 **不执行 VACUUM**，不会长时间锁库，也不影响白天的备份/导入；完整性检查失败只记录日志，
  不会自动修复或删除数据库，请结合「系统管理 → 运维与监控」排查。
