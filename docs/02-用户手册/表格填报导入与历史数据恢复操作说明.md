# 表格填报导入、导出与历史数据恢复操作说明

> 适用版本：v1.18.35 起（R57 / R61）
> 适用页面：**数据导入**（`/import/data`）、**一户一档**列表、**报表模板**（下载/上传填报）、**备份与恢复**。

## 1. 适用范围与能力总览

| 能力 | 入口 | 说明 |
|------|------|------|
| 模板下载 | 数据导入页 → 模板区 | 帮扶村 / 项目 / 资金 / 学校 / 一户一档 |
| 表格填报导入 | 数据导入页 → 上传区 | 增量导入（按名称去重）或全量导入（超管） |
| 单条导出填报 | 数据导入页 → 导出填报表格（填写 1 个 ID） | 导出官方模板表头 + 该条数据 + `ID` 列 |
| 批量导出填报 | 同上（ID 留空） | 导出当前数据权限范围内全部记录（上限 5000 行） |
| 填报后回导 | 导出 → 修改 → 上传 | 带 `ID` 的行更新原记录；无 `ID` 的行新增 |
| 历史备份恢复 | 系统管理 → 备份与存储 → 备份 | 兼容旧版备份路径与旧 schema |

> 数据范围：导出与导入都按当前账号的数据权限执行；非管理员不能导入，越权 ID 会按失败处理并提示。

## 2. 模板下载与填写规则

1. 进入 **数据导入** 页，选择实体类型，点击 **下载模板**。
2. 官方模板结构：前几行为标题/填报单位说明，**表头行为加粗的字段名**，表头下方有一行
   **示例行**，最后一列带 `← 示例行（导入时自动跳过）` 注释。
3. 填写规则：
   - **推荐在示例行下方新增数据行**填写；
   - 若确实要直接在示例行上填写：**替换首列的示例值**（如「某某部门」「示例部门」「某某村」
     等），其余单元格填真实数据即可；末尾的「示例行」注释可以保留——系统只有在
     **首列仍是示例值且该行带示例注释**时才整行跳过，不会误丢真实数据；
   - 必填列以 `*` 开头（如帮扶村模板的 `*各部门各单位`、`*具体帮扶单位`、`*定点帮扶村`）；
   - 枚举列按模板下拉/说明填写中文值（如资金类型、项目状态、学校类型）；
   - 日期建议 `YYYY-MM-DD`，布尔列填「是/否」。
4. 空行、页脚说明行（含「填写说明 / 填报说明 / 帮扶管理信息系统 v」）会自动跳过。

## 3. 表格填报导入（新增 / 全量）

1. 数据导入页选择类型与模式：
   - **增量导入（incremental）**：按名称去重，已存在的名称跳过；适合日常补录。
   - **全量导入（full）**：仅超管可用，导入前会软删除本组织对应数据；适合初始化或整体替换。
2. 选择 `.xlsx`/`.xls` 文件上传，系统先解析并给出结果：
   - 成功 / 失败 / 跳过条数与逐行错误；
   - **解析不到任何数据行时直接返回 400**，提示「模板中的示例行不会导入，请在示例行下方新增
     数据行（或删除示例行后填写）」，不会再出现“提示成功但入库 0 条”。
3. 导入成功后系统自动触发一次即时备份（便于回退）。

### 一户一档导入

- 入口：数据导入页选择「一户一档」，或一户一档列表页点击「表格填报」。
- 帮扶村按「村名 + 县 + 乡镇」解析；同名多村会报错，请在模板中补充县/乡镇区分。
- 户编号在同一村内唯一；留空时按「村 + 户主姓名」去重。

## 4. 单条导出、批量导出与回导

### 4.1 导出填报表格

1. 数据导入页 → **导出填报表格（修改后可回导）**；
2. 选择类型；
3. **记录 ID（可选）**：
   - 留空：批量导出当前数据权限范围内全部记录（单次上限 5000 行）；
   - 填 `123`：只导出 ID=123 的单条记录；
   - 填 `123,456`（中英文逗号或空格均可）：导出指定多条。
4. 点击 **导出填报表格**，得到官方模板表头 + 数据 + 末尾 `ID` 列的 Excel。

> 也可以从各业务列表的「导出」获得台账数据，但台账表头与导入模板表头不同，
> **回导请使用本页的「导出填报表格」**，或确保表头与官方模板一致。

### 4.2 修改后回导

1. 在导出的 Excel 中修改单元格（不要改动表头；`ID` 列可保留）；
2. 回到数据导入页，选择同一类型上传；
3. 回导规则：
   - **带 `ID` 且能在当前数据权限范围内找到**：更新原记录（不新增、不改变归属组织/创建人）；
     更新行计入成功数；
   - **ID 不存在或不在权限范围内**：该行按失败处理并提示 `ID=… 不存在或无权限`，不影响其他行；
   - **无 `ID`**：按增量规则去重后新增（或全量模式新建）。
4. 支持的实体：帮扶村、项目、资金、学校、一户一档。

## 5. 历史版本数据恢复

### 5.1 恢复前准备

1. 先对**当前库**做一次备份（系统管理 → 备份与存储 → 备份），避免恢复失败后无回退点；
2. 确认备份文件来自本系统（`.zip`/加密备份包），记录其来源版本（发布说明/文件名）；
3. 恢复必须在维护窗口内进行：期间写请求返回 503，读请求正常，在途请求会先等待归零。

### 5.2 恢复步骤

1. 系统管理 → 备份与存储 → 备份 → **恢复**；
2. 选择备份包，输入加密包密码（如有）；
3. 红色警告弹窗二次确认；
4. 恢复完成后系统自动校验 schema 版本并重启相关服务；如备份来自更老版本，
   会按迁移链升级到当前 schema 后再开放写入。

### 5.3 兼容口径

- 备份 manifest 自 v1.18.35 起写入 `format_version=2 / app_version / schema_revision`；
- 旧备份的数据库文件按以下顺序自动定位：
  标准路径 → `data/assistance.db` → `data/assistance_management.db` → 根目录同名文件 →
  `data` 下唯一的 `.db`；
- 无 `alembic_version` 表的极老备份按「可升级」处理，不会被直接拒绝；
- 仅当备份 schema 高于当前程序且不在当前迁移链上时才拒绝恢复（防止降级损坏）；
- SQLite 版本兼容：低于 3.35 不支持 `DROP COLUMN`、低于 3.25 不支持 `RENAME COLUMN` 时，
  迁移自动改用 `batch_alter_table` 重建表。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 导入提示成功但列表 0 条 | 直接改了示例行且注释仍在 | 删除「示例行」注释或在示例行下方新增数据行 |
| 上传后 400「未解析到任何数据行」 | 只有标题/示例/说明行 | 在示例行下方新增真实数据行 |
| 回导后原记录没变 | 删除了 `ID` 列或 ID 不在权限范围 | 保留 `ID` 列；用本组织账号导出/回导 |
| 导入报「村名匹配到多个帮扶村」 | 同名村跨县/乡镇 | 模板补全县、乡镇字段 |
| 恢复时提示 schema 过新 | 备份来自更高版本程序 | 升级到对应版本后再恢复，或使用同版本备份 |

## 7. 验证方式与预期结果

- **导入**：上传含 1 条真实数据的模板 → 返回 `success_rows=1`，列表可见；上传仅示例行文件 → 400；
- **导出**：单条导出文件含该条 `ID` 与数据；批量导出含全部（≤5000）行且表头与模板一致；
- **回导**：修改导出文件中的一个字段后上传 → 原记录被更新、总数不增加；未知 ID → 该行失败并提示；
- **历史恢复**：用旧版备份包恢复 → 恢复到维护窗口结束、schema 升级完成，关键表行数与备份一致；
- **回归**：后端全量 12 段、前端全量、三层对齐与文档数字门禁全部通过（发布门禁口径）。
