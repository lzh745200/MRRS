# 权限 · 机构 · 角色 · 用户 · 注册登录 操作说明

> 适用版本：v1.16.3 起　｜　入口：侧栏「系统管理」→「组织与权限」
> 相关文档：[系统管理操作说明](./系统管理操作说明.md)（6 聚合页 / 30 功能的分组与逐项操作）

---

## 一、先搞懂：这个系统的权限是 4 层叠加的

登录后能看什么、能改什么，由这 4 层**依次覆盖**（上层优先）：

| 优先级 | 层 | 在哪配 | 作用范围 |
|---|---|---|---|
| ① 最高 | **用户级菜单白名单** `allowed_menus` | 用户与组织 → 行内「权限」抽屉 | 只对这个用户生效 |
| ② | **权限包**（启用中） | 角色与权限 → 权限包管理 | 绑定到的用户 / 角色 |
| ③ | **角色默认菜单** | 角色与权限 → 角色管理（只读查看） | 该角色的所有人 |
| ④ 兜底 | **系统角色** `role` | 用户与组织 → 编辑用户 | 决定"是否管理员/是否只读" |

另有两条与菜单无关的约束：

- **数据范围** `data_scope`：决定能看到**哪些组织的数据**（不是哪些菜单）
  - `all` 全部 ｜ `org_children` 本组织及下级 ｜ `org` 本组织 ｜ `self` 仅本人
  - 服务端强制：列表/导出/详情都会过滤；越权访问返回 403 或 404
- **单位授权矩阵**（R33，仅多机部署用）：上级给下级单位下发「模块 × 级别」，下级导入后**只读执行**

> 一句话记忆：**系统角色定身份 → 数据范围定数据 → 权限包/白名单定菜单**。

### 4 个系统角色（内置，不可新建）

| 角色值 | 名称 | 能力 |
|---|---|---|
| `super_admin` | 超级管理员 | 全量菜单 + 全量数据；可重置其他超管密码；不受组织子树限制 |
| `admin` | 管理员 | 管理本单位及下级：用户/组织/权限包/备份等；数据范围默认收敛到本组织及子树 |
| `user` | 普通用户 | 业务功能；数据默认仅本人（或按 data_scope） |
| `viewer` | 只读用户 | 可看不可写：服务端对写请求直接 403 |

> 历史角色值（`approval_leader`/`manager` → `admin`，`operator` → `user`）由 `normalize_role()` 自动归一化，无需手工改库。

## 二、机构（组织）管理

**入口**：组织与权限 → 组织与单位 → 组织机构（`/organizations`）

### 新增机构
1. 左侧组织树选中「上级组织」（新建根组织则选「全部」）；
2. 右上「新增」→ 填 **名称**（必填）、**编码**（建议填，单位授权包按编码比对）、**类型**、**排序**；
3. 保存后系统自动维护 `path` 与 `level`（数据权限的根，缺失会导致"成员一律无权限"）。

### 编辑 / 移动
- 行内「编辑」可改名称、编码、排序、上级组织；
- **变更上级会影响整棵子树的数据可见范围**，操作前先确认影响面；
- 停用（`is_active=false`）后不再出现在下拉与列表中，历史数据仍保留。

### 删除（高危）
- 行内「删除」→ 需要**输入当前登录密码**二次确认（走请求头 `X-Confirm-Password`，不进访问日志）；
- 名下**有子组织、项目或用户**时禁止删除（提示先转交/先删子级）；
- 删除是**逻辑删除**（`is_active=false`），不会物理清除数据；
- 该操作会写入审计日志，动作名 `organization_delete`。

### 成员
- 详情页「成员」页签可查看本组织用户；「移除成员」需管理员；
- 用户归属组织决定了它的 `org` / `org_children` 数据范围。

## 三、角色管理

**入口**：组织与权限 → 权限配置 → 角色管理（`/system/roles`，等价 `/system/users` 的「角色管理」页签）

系统里有两套"角色"，别混：

| 类型 | 说明 | 能否新建 |
|---|---|---|
| **系统角色** | 上面 4 个（super_admin/admin/user/viewer），决定身份与默认菜单 | ❌ 内置固定 |
| **RBAC 角色** | 自定义角色，用来**批量打权限点/菜单** | ✅ 可增删改 |

### RBAC 角色操作
- **新建**：名称 + 描述 + 勾选权限点（如 `user:read`、`funds:write`）→ 保存；
- **绑定用户**：角色卡片 → 用户列表 → 添加用户（也可在用户权限抽屉的「角色分配」里操作）；
- **删除**：先解绑所有用户，否则拒绝；系统角色不可删除；
- 角色默认菜单可在「角色管理 → 菜单」里核对（只读，菜单唯一源在后端）。

## 四、用户管理

**入口**：组织与权限 → 账号与组织 → 用户与组织（`/system/users`）

### 新增用户
1. 右上「新增用户」→ 用户名、姓名、**角色**、**组织**、手机号（可选）；
2. 初始密码需满足策略：**≥12 位 + 大写 + 小写 + 数字 + 特殊字符**（`!@#$%^&*()-_=+[]{}|;:,.<>?`）；
3. 保存后建议勾选「下次登录强制改密」（`must_change_password`），首次登录会被强制跳转改密页；直连 API 也会被拦。

### 编辑 / 停用
- 行内「编辑」可改姓名、角色、组织、状态；
- **停用**（`is_active=false`）后立即无法登录，令牌在下次校验时失效；
- 删除用户同样受"超管只能由超管操作"与"跨组织越权守卫"约束。

### 审核待注册用户
- 页面顶部出现「待审核用户」横幅时，说明有人自助注册（见第六节）；
- 「通过」= 启用并可登录；「驳回」= 保持不可登录；
- 待审核列表接口：`GET /api/v1/users/pending/list`。

### 重置密码（高危）
- 行内「重置密码」→ 生成或手输新密码 → 点「确认重置」后**必须手工输入目标用户名**才会执行；
- 执行后该用户**全部登录令牌立即失效**、且下次登录强制改密；
- 新密码会自动复制到剪贴板并弹窗展示（只显示一次，注意及时转交）；
- 写入审计日志，动作名 `admin_reset_password`。

### 权限抽屉（一体化）
行内「权限」打开抽屉，顶部「生效概览」一屏给出：用户（含姓名）、系统角色、数据范围、菜单权限来源（自定义/沿用角色默认 + 生效项数）、RBAC 可选角色数。

| 页签 | 作用 |
|---|---|
| 角色分配 | 给该用户挂/摘 RBAC 角色 |
| 权限配置 | 勾选权限点（如导出、审批） |
| 菜单可见性 | 自定义该用户可见菜单（对应 `allowed_menus`，优先级最高） |
| 系统角色 | 改 role 与 data_scope（仅管理员可见） |

### 会话管理
- 详情/行内「会话」可查看在线会话并「强制下线」（吊销单个会话）；
- 改密、重置密码、角色变更会提升 `token_version`，**旧令牌整体失效**；
- 顶栏「退出登录」会登出当前会话。

## 五、权限配置（权限包 + 菜单）

**入口**：组织与权限 → 权限配置 → 权限包管理（`/system/permission-packs`）

### 新建权限包
1. 「新建」→ 填名称、描述；
2. 勾选**菜单 key**（来自后端菜单单一源，覆盖 7 板块 / 全部页面与 30 个系统管理功能）；
3. 绑定到「用户」或「角色」→ 启用；
4. 支持**导出/导入**（JSON），便于多机批量下发。

### 生效规则
- 启用中的权限包才生效；同一用户多个权限包取**并集**；
- 用户的 `allowed_menus` 一旦自定义，**优先于**权限包与角色默认；
- 审批类等操作权限点（`xxx:read` / `xxx:write`）与菜单可见性相互独立：可见 ≠ 可写。

### 菜单管理（只读）
- 菜单唯一源是后端 `menus.py`；「菜单管理」页用于核对结构与 key，不作为编辑入口；
- 新增页面必须走：后端菜单 → 前端路由 `meta.menuKey` → 页内组件映射，三道门禁（菜单对齐 / console tab 映射 / 死链门禁）会校验。

## 六、注册与登录

### 6.1 登录
- 地址：安装后默认 `http://<本机IP>:8000`（开发态 5173）；
- 出厂账号 `admin` / `zgcZGC733035#`（首登强制改密；生产请用 `DEFAULT_ADMIN_PASSWORD` 覆盖）；
- **失败锁定**：连续 5 次密码错误锁定 30 分钟（`MAX_FAILED_LOGIN_ATTEMPTS` / `ACCOUNT_LOCKOUT_MINUTES` 可配），锁定期间即使密码正确也拒绝；
- 登录成功返回 JWT；后续请求带 `Authorization: Bearer <token>`，写请求还需 CSRF Token（`GET /auth/csrf-token`）。

### 6.2 首次登录 / 修改密码
- 新账号或被管理员重置密码的账号：`must_change_password=true` → 登录后强制跳到「修改密码」，未改密前其它接口被拦；
- 自助改密：右上头像 →「个人中心」→ 修改密码，需输入旧密码；
- 密码策略同上（≥12 位 + 四类字符）。

### 6.3 自助注册（可选）
- 登录页「注册」→ 填用户名、姓名、**通行码**（8/32 位，由管理员在「机器码管理」生成）、机器码（可自动读取）；
- **通行码一次性有效**，用后即废；多机部署需统一 `PASS_CODE_SECRET`；
- **来源门禁**：非回环地址（非本机）注册时，若服务器未配置 `PASS_CODE_SECRET` → 直接 403「禁止非本机自助注册」，防止内网任意人开号；
- 注册成功后的账号为**待审核**状态，需管理员在「用户与组织」顶部横幅审核通过才能登录；
- 机器码不稳定（重装系统/换硬件）时，后端有三级回退：机器码+通行码 → 仅通行码匹配 pending 记录并自动重绑。

### 6.4 两步验证（2FA）
- 个人中心 →「两步验证」→ 启用：扫码/手输密钥 → 输入 6 位验证码完成绑定，同时生成一次性**备用码**（请离线保存）；
- 登录时若已启用 2FA，会进入验证码页（`POST /auth/two-factor/verify-login`）；
- 管理员可在用户页「重置 2FA」（用户丢失设备时）；关闭 2FA 需当前密码 + 验证码。

### 6.5 忘记密码
- 登录页「忘记密码」→ 需**用户名 + 机器码/通行码**校验通过后重置；
- 兜底路径：联系管理员在「用户与组织」里「重置密码」（需手工输入用户名确认）。

### 6.6 只读账号（viewer）
- 菜单可见但所有写接口返回 403（服务端中间件强制，前端也会禁用保存按钮）；
- 导出等敏感操作同样受限，具体取决于授权矩阵与权限点。

## 七、单位授权（R33 · 多机部署）

**入口**：组织与权限 → 组织与单位 → 单位授权配置 / 导入授权包

### 上级单位：配置并下发
1. 打开「单位授权配置」，在顶部**下拉里选择要授权的单位**（可按名称/编码搜索；v1.16.3 起不再要求手抄数字 ID，必要时可点「手工输入 ID」切换回旧方式）；
2. 点「加载」→ 出现「模块 × 级别」矩阵：**可操作**（可见可写）/ **只读**（可见写 403）/ **不开放**（菜单不下发）；
3. 调整后「保存矩阵」（替换语义，版本号自增）；
4. 「导出授权包」得到签名 JSON，经离线介质交给下级。

### 下级单位：导入执行
1. 打开「导入授权包」→ 选文件 → 校验签名与版本（**禁止降级**）；
2. 导入成功后本机按上级矩阵**只读执行**，本机不再提供编辑入口；
3. 前置：下级机需配置 `GRANT_PUBKEY`（公钥），`GRANT_ALLOW_UNSIGNED` 必须为 false。

### 注意
- 两侧**单位编码必须一致**，否则导入后匹配不上；
- 授权包版本严格单调递增，重复导入旧包会被拒；
- 选择单位后切换单位会清空上一个单位的矩阵（防止把 A 的矩阵存到 B 名下）。

## 八、常见提示与排错

| 提示 / 现象 | 原因 | 处理 |
|---|---|---|
| 请先填写有效的单位 ID | 旧版「单位授权配置」要求手输数字 ID，或输入非正整数 | **v1.16.3 起改为下拉选择单位**；仍用工 ID 时切「手工输入 ID」并填 `organizations.id`（组织机构页可见） |
| 单位不存在（404） | 目标组织不在你的组织子树内，或被停用 | 在「组织机构」确认组织存在且在你的子树；必要时找超管 |
| 403 仅管理员可执行此操作 | 当前账号不是 admin/super_admin | 换管理员账号，或让管理员调整角色 |
| 403 viewer 只读 | 当前账号是 viewer | 需要写操作请升级角色 |
| 账户已锁定 | 连续 5 次密码错误 | 等 30 分钟自动解锁，或管理员重置密码 |
| 服务器未配置 PASS_CODE_SECRET，禁止非本机自助注册 | 安全门禁：远端自助注册需配置该密钥 | 由管理员在本机开号，或部署时配置 `PASS_CODE_SECRET` |
| 通行码无效或已被使用 | 通行码一次性；或机器码漂移 | 重新生成通行码；后端会自动重绑 pending 记录 |
| 密码必须包含特殊字符 | 未满足密码策略 | 用 ≥12 位 + 大小写 + 数字 + 特殊字符 |
| 登录后一直让改密码 | `must_change_password=true` | 完成改密即可（改密后自动解除） |

## 九、安全约定（管理员必读）

1. **最小授权**：优先用权限包，不要逐个用户改 `allowed_menus`；
2. **超管收敛**：只有 super_admin 能重置其他超管的密码；部门管理员只能管本子树；
3. **高危操作留痕**：删除组织、恢复备份、轮换密钥、重置密码均写审计日志（安全与审计 → 安全审计可检索）；
4. **令牌失效**：改密 / 重置 / 角色变更会让旧令牌整体失效，异常登录务必先重置密码；
5. **离线段**：多机同步时 PII 字段以密文出包，各机 `ENCRYPTION_KEY` 必须一致，否则对端解密失败（界面显示 `enc.v1:…`）；可用「系统设置 → PII 密钥」导出/导入密钥。
