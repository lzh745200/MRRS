# 介质数据包导入与系统自检 操作说明

> 适用版本：v1.17.0 起
> 场景：**完全离线**单机部署，上下级之间通过 U 盘/移动硬盘等**介质**传递数据包与授权包

---

## 一、先理解：介质导入为什么需要"查重 + 台账"

离线环境下没有中心服务器，一份数据包可能在几台机器之间来回拷贝。过去常见三类事故：

| 事故 | 过去的表现 | 本版的处理 |
|---|---|---|
| **同一个包被导入两次** | 第二次仍提示"导入成功"，实际重复写入或全部跳过 | 按**整包校验和**识别，重复导入直接拦截（409），需显式放行 |
| **导错机器（把上级/邻县的包导进本单位）** | 包能导入，数据挂到了错误的组织树上，事后极难发现 | 比对**包内单位码**与本机单位码，不一致默认阻断 |
| **导完之后说不清"谁在什么时候导了什么"** | 只有一条泛泛的审计记录 | 每次导入写**台账**（类型/来源单位/校验和/记录数），确认导入再写**回执**（接收单位、冲突策略） |

---

## 二、导入数据包（接收方）

### 步骤

1. 进入 **数据管理 → 接收数据包**
2. 点「本地导入」，选择介质上的 `.zip` 数据包
3. 系统自动依次执行：
   - **格式校验**（必须是由本系统导出的标准包）
   - **完整性校验**（校验和；配置了公钥时还验签）
   - **查重**（整包 SHA256 是否导入过）
   - **单位码核对**（包内 `org_code` vs 本机单位码）
4. 校验通过后进入预览，确认无误点「确认导入」
5. 导入完成后可查看「接收记录」

### 三种拦截与处理

| 提示 | 含义 | 怎么处理 |
|---|---|---|
| **该数据包已于 X 由 Y 导入过** | 同一份包之前已成功导入 | 确认确实需要再导一次（例如上次导入后本机数据被清空）→ 重新上传时选择「仍然导入」；否则放弃 |
| **数据包来源单位码为 A，与本机单位码 B 不一致** | 包不是发给本机的 | **优先找上级确认是否发错**；确属本机该收（如上级代发）→ 选择「仍然导入」 |
| **校验和/签名不匹配** | 包在传输中损坏，或被替换过 | **不要导入**，让上级重新导出并通过干净介质传递 |

> 两个"仍然导入"都要求操作人显式确认，且会记录到台账，便于事后追溯。

## 三、导入授权包 / 权限包 / 配置包

四类包的查重规则一致，位置与差异如下：

| 包类型 | 入口 | 查重时机 | 说明 |
|---|---|---|---|
| 数据包 | 数据管理 → 接收数据包 | 上传时 | 包内单位码也会核对 |
| 授权包 | 系统管理 → 组织与权限 → 导入授权包 | 上传时 | 授权包用于下级执行上级下发的模块权限 |
| 权限包 | 系统管理 → 组织与权限 → 权限包管理 → 导入 | **确认导入时** | 先允许预览包内容，确认才查重（避免连"看看里面有什么"都做不到） |
| 配置包 | 系统管理 → 系统设置 → 配置包 | 导入时 | 系统配置项批量恢复 |

## 四、系统自检（装完机第一件事）

**入口**：系统管理 → 系统设置（页面顶部「系统自检」卡片）

点「重新检查」会一次性体检 **6 项**：

| 检查项 | 检查什么 | 出现异常怎么办 |
|---|---|---|
| **组织单位码** | 缺失 / 格式错误 / 层级与编码不符 / 重复 | 到「组织与单位」补齐或修正（6 位行政区划代码，创建后不可改） |
| **组织层级** | 是否跨级挂接、根组织是否为省级 | 逐级挂接：省 → 市州 → 县市 |
| **待审核账号** | 有多少账号未启用/待审核 | 到「用户与组织」审核 |
| **账号锁定** | 是否有人被连续登录失败锁定 | 用户行点「解锁」 |
| **PII 密钥** | 密钥指纹是否可读 | 多机部署需与上级一致，否则跨机数据解不开 |
| **介质导入** | 近 30 天导入失败次数 | 到「接收记录」核对失败原因 |

**结论三态**：正常（绿）/ 提醒（黄，可继续用但建议处理）/ 异常（红，必须先处理）。

> 自检是**只读**的，不会修改任何配置，可以随时点。

## 五、多机部署的推荐流程

```
上级（省/市州）
  1. 配置本单位信息（单位码 = 行政区划代码）
  2. 导出数据包 / 授权包
  3. 记录校验和（SHA256），登记交接
        │  介质（U 盘）
        ▼
下级（市州/县市）
  4. 系统自检（确认本机组织/账号/密钥正常）
  5. 导入包 → 遇到 409 先核对来源单位码
  6. 确认导入 → 生成回执
  7. 回执带回上级登记，完成闭环
```

### 注意事项

- **单位码必须一致**：上级导出时包内记录的是上级单位码；下级导入校验的是**目标单位**（本机）单位码，两者不同是**正常**的，系统比对的是"包内来源"与"本机目标"是否一致。
  若上级替下级代发数据，会出现不一致 → 此时用「仍然导入」并在台账备注原因。
- **介质专用**：建议专盘专用、使用前后杀毒、登记编号。
- **密钥一致**：多机同步时 `ENCRYPTION_KEY` 必须一致，否则 PII 密文在对方机器上解不开（自检的「PII 密钥」项就是查这个）。

## 六、常见问题

**Q：为什么我导入时被拦了，但上次同样操作是成功的？**
A：上次成功后，这个包的校验和已进台账。确认本机数据状态后再决定是否放行重复导入。

**Q：能查到"是谁导入了哪个包"吗？**
A：能。安全与审计 → 安全审计中按动作 `package_import` / `package_receipt` 筛选，或到「系统自检」看近 30 天导入概况。

**Q：导入后能撤销吗？**
A：不能自动撤销。数据包导入是按冲突策略合并的；如需回退，用导入前的数据库备份恢复（备份与存储 → 恢复备份，需维护窗口）。

**Q：老的数据包没有单位码字段怎么办？**
A：自检与导入会提示"未声明来源单位码"——属于**无法判定**，不阻断导入，但建议让上级用新版本重新导出。
