# 完全离线环境下的功能适用性核查报告

> 核查对象：帮扶管理信息系统（Electron + FastAPI + Vue3 单机离线桌面应用，版本基线 v1.15.16）
> 核查日期：2026-10-21
> 核查问题：**系统中有哪些功能在"完全离线"环境下不适用？逐一核查，并给出完善方案。**
> 方式：只读静态审计（grep / read / 列目录 / 只读 `python -c` / 解包产物核对），未修改源码、未运行 pytest/npm build、未启动服务。
> 后续处置：本报告指出的问题已于同日落到实现，见 [离线OCR与瓦片预置方案.md](离线OCR与瓦片预置方案.md)。

---

## 一、总体结论

**这套系统在架构上确实是"真离线"的，不是"假装离线"。** 全仓真实出网点只有 3 处：SMTP 邮件、HTTP Webhook（钉钉/企业微信）、以及一处**本机回环**端口探活；前端无任何 CDN / 在线字体 / 在线地图 SDK；地图是 ECharts + 本地 GeoJSON；数据交换全靠本地加密包；Windows 安装、首次启动、日常运行、升级（覆盖安装）全流程无联网硬依赖。

真正"离线不适用"的功能只有一个小集合：

| 级别 | 条数 | 编号 |
|---|---|---|
| 致命 | **0** | — |
| 严重 | 4 | 瓦片假成功（A8/C2）、瓦片资产缺失（C1）、麒麟无 OCR（C3）、麒麟 deb 依赖（D2） |
| 一般 | 8 | A4（误开 Redis 拖慢启动）、A11（邮件偏好）、B1/B2（瓦片页文案、消息外链）、C4（对比图缺字）、D3（瓦片空壳）、D4（缺包无自愈）、D5（无增量升级） |
| 提示 | 30+ | 死配置、误导性命名、无害外链字符串 |

**最该先处理的 5 件事（本次均已进入处置）：** ① 地图瓦片"下载"假成功；② 瓦片资产不存在；③ 麒麟 Electron deb 的 18 个系统库依赖；④ 邮件/Webhook 告警无离线开关且为死代码；⑤ 文档宣称"Leaflet 离线瓦片双模式"与实现不符。

## 二、判定口径

| 级别 | 定义 |
|---|---|
| **致命** | 离线时功能完全不可用且无降级，或阻塞主流程/启动 |
| **严重** | 功能不可用但有降级/仅特定平台，或**给用户假成功**这类主动误导 |
| **一般** | 功能可用但体验降级 / 需人工介入 / 与文档不符 |
| **提示** | 无实际影响；仅代码/文档里存在外网字符串、死配置、命名误导 |

## 六、离线特有的"隐性风险"（不联网也会坏）

来自仓库既有深度探测（`.scratch/w18-deep-probe/02-offline-runtime.md`）与本轮复核：

| 风险 | 一句话 |
|---|---|
| 系统时钟漂移 | 离线机无 NTP；影响"最近 N 天"统计、调度、2FA（TOTP ±30s）、JWT 有效期。`startup/preflight.py:75-93` 只检测"落后数据 >1 天"且仅告警 |
| 换机/重装后 PII 密文不可解 | `runtime_secrets.json` 不在备份包内，9 列 PII 显示 `enc.v1:` 乱码且不报错 |
| 日志/备份目录分叉 | Electron userData 与后端 `%LOCALAPPDATA%` 两套路径，按文档取日志取不到 |
| 麒麟 standalone 数据目录权限 | `HOME` 指向安装目录 → 备份/密钥落 `/opt` 不可写 → 装机即坏 |
| SQLite 落网络盘/OneDrive | `PRAGMA journal_mode=WAL` 返回值被丢弃，WAL 不可用无感知 |
| 调度器无"错过补跑" | 22:00 关机、次日 08:00 开机 → 02:00 自动备份永远不执行 |
| 对比图中文缺字 | `media_service.py:449 ImageFont.load_default()` 无 CJK |
| PDF 中文依赖阅读器 CID 替代 | reportlab 用 `STSong-Light`（无 .ttf），极简阅读器可能异常 |
| 安装包体积与升级成本 | 解包 706MB / 安装包约 230MB；无增量补丁，每次全量覆盖 |
| Electron 拼写检查 | 未设 `spellcheck:false`，部分平台 Chromium 会尝试拉词典（失败仅无拼写检查） |
