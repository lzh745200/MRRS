## 1. 为什么更新

v1.18.66 / v1.18.67 交付了两组会改变汇报口径的能力与边界：

1. **账号开通包开箱即用**：`ACCOUNT_PACKAGE_ENABLED` 默认开启；首次签发时自动生成并持久化
   Ed25519 私钥，不再要求配置 `ACCOUNT_PACKAGE_SIGNING_KEY`；包内嵌签发公钥，导入端在首次
   导入时通过**指纹带外核对**建立信任，之后不再重复询问。
2. **角色与注册口径收敛**：系统固定四个角色（超级管理员 / 系统管理员 / 普通用户 / 访客）；
   不再提供自助注册，账号只能由管理员创建或通过账号开通包离线导入；RBAC 角色仅服务权限包，
   不影响 `users.role`；权限包导入默认不写账号级角色/数据范围/权限。

三份 PPT 原先停留在 v1.18.65，页脚版本号、测试规模与角色说明都已过时，因此统一校准。

## 4. 复现方式

三份 PPT 没有可用的历史生成器（`docs/build_ppt.js` 已不在仓库，`projects/*/build_slides.py`
只产出 SVG）。本次使用 `python-pptx` 做**段落级文本替换**：

1. 读取 deck，递归遍历 `slide.shapes` 与 group shape；
2. 对每个段落拼接 `run.text`，命中替换表后把新文本写入第一个 run、清空其余 run，
   保留段落对齐/行距与首个 run 的字体；
3. 对角色名等变长文本，按需加宽文本框（`shape.width`），并设置 `word_wrap=True`；
4. 保存后用 `scripts/ppt_overflow_check.py` 复检。

脚本一次性执行，未写入仓库；替换表与逐页改动见本文第 2 节。若后续版本只需更新版本号/测试数字，
按第 2.1 节的三组值做同样替换即可。
