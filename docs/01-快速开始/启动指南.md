## 🚀 一键启动

### Windows（推荐）

```bat
scripts\start-all.bat     :: 启动后端(8000) + 前端(5173)，各自独立窗口
scripts\stop-all.bat      :: 停止占用 8000/5173 端口的服务
```

说明：
- `start-all.bat` 内部调用 `scripts\run-backend.bat` / `scripts\run-frontend.bat`；
- 后端解释器由 `scripts\find-python.bat` 显式解析（优先 `backend\.venv\Scripts\python.exe`，
  其次 `py -3.11`；都找不到时报错并打印修复指引）——**不依赖 PATH 里的裸 `python`**
  （W24 构建缺陷：本机 PATH 的 python 曾指向已删除的 32 位安装，裸 python 调用不可复现）。

首次使用先初始化开发环境：

```bat
scripts\dev-setup.bat        :: 建 backend\.venv、装依赖、装 pre-commit、复制 .env
```

### Linux / macOS

```bash
bash scripts/dev-setup.sh    # 初始化
make dev                     # 后端 uvicorn(8000) + 前端 npm run dev(5173)
```

```bash
# 后端（项目 Python 由 backend/.venv 提供；PATH 里的裸 python 不可信）
```

## 🛠️ 手动启动

### 后端服务

```bash
cd backend
# 首次：创建 venv 并安装依赖（Windows 用 .venv\Scripts\、Linux/macOS 用 .venv/bin/）
# 数据库在启动时自动执行 Alembic 迁移，无需 init_db.py
.venv/Scripts/python.exe start.py        # Windows
# .venv/bin/python start.py              # Linux/macOS
```

### 前端服务

```bash
cd frontend
npm install       # 首次
npm run dev       # Vite 开发服务器（5173）
```

## ❓ 常见问题

### 1. 端口被占用

**问题**：`Address already in use`

**解决方案**：
- 修改后端端口：`uvicorn app.main:app --port 8001`
- 修改前端端口：`npm run dev -- --port 5174`

### 2. Python 模块未找到

**问题**：`ModuleNotFoundError: No module named 'xxx'`

**解决方案**：
```bash
cd backend
pip install -r requirements.txt
```

### 3. Node.js 依赖安装失败

**问题**：`npm install` 失败

**解决方案**：
```bash
cd frontend
rm -rf node_modules package-lock.json  # Linux/Mac
# 或
rmdir /s /q node_modules && del package-lock.json  # Windows

npm install
```

### 4. 数据库初始化失败

**问题**：`Failed to initialize database`

**解决方案**：
```bash
cd backend
# 删除现有数据库
del data\*.db  # Windows
# 或
rm data/*.db  # Linux/Mac

# 重新初始化
python init_db.py
```

### 5. CORS 错误

**问题**：浏览器控制台显示 CORS 错误

**解决方案**：
检查 `backend/.env` 文件中的 CORS 配置：
```env
CORS_ORIGINS=http://localhost:5173,http://localhost:3000
```

### 6. 前端无法连接后端

**问题**：`ERR_CONNECTION_REFUSED`

**解决方案**：
1. 确认后端服务已启动
2. 检查后端端口是否正确（默认 8000）
3. 检查防火墙设置
4. 查看 `frontend/.env` 中的 API 地址配置

## 📝 开发模式 vs 生产模式

### 开发模式

- 后端：使用 `--reload` 参数，代码修改自动重启
- 前端：使用 `npm run dev`，支持热更新
- 适合日常开发

### 生产模式

- 后端：不使用 `--reload`，性能更好
- 前端：使用 `npm run build` + `npm run preview`
- 适合部署

## 💡 提示

1. **首次启动**：建议使用一键启动脚本，会自动完成所有初始化
2. **日常开发**：可以单独启动前后端，提高启动速度
3. **代码质量**：提交代码前运行代码质量检查
4. **日志查看**：开发模式下，日志会在终端中实时显示
5. **端口冲突**：如果端口被占用，可以修改配置文件中的端口号
6. **页面白屏**：如果遇到 `setAttribute('0')` 错误，请清除浏览器缓存并重启前端开发服务器
7. **注册问题**：如果注册时提示“通行码无效”，请确认通行码未使用过；系统已支持机器码变化自动适配
