# ADR-0008: 破窗恢复（机器码重置密码）安全边界

日期：2026-08-23 · 状态：Accepted · 关联工单：w1-security-redline/001

## 背景

`POST /machine-code/reset-password-with-machine-code` 是离线单机部署下唯一的
忘记密码恢复通道（前端 ForgotPassword 页面全流程依赖）。检测发现其可被远程
未认证两步利用（公开校验码 → 重置任意账号并返回明文密码），构成完整认证绕过链。

## 决策

保留破窗通道，但施加四重边界：

1. **限流真实生效**——`check_rate_limit` 签名收紧为 key 必填（fail-closed）
2. **仅限本机**——门禁基于 `request.client.host`（TCP 对端地址），
   不读取 X-Forwarded-For 等可伪造头
3. **管理员排除**——admin/super_admin/is_superuser 账号一律 403，
   走管理端重置流程；防止静默接管最高权限
4. **审计留痕**——每次成功重置写 write_work_log，日志含目标用户名

一次性明文密码仅在满足以上全部条件的本次响应中返回
（must_change_password 强制首次登录改密）。

## 否决的替代方案

- **完全移除明文返回**：破坏唯一恢复通道，超级管理员忘密即砖
  （现有应急路径 main.py 引导初始化会产生 H4 明文临时文件问题）
- **一次性 reset token 替代**：与直接返回密码等价风险（拦截者同样可以改密），
  增加复杂度无安全增益
- **校验码彻底移除**：校验码本身由源码内确定性算法生成，移除只是象征性；
  真正的门禁是 loopback + 管理员排除

## 后果

- 远程攻击面归零（后端绑定 127.0.0.1 时该端点对外部网络不可达且不可用）
- 本机操作者仍可自助恢复普通账号——与产品设计意图一致，
  且每次动作留痕可审计
- 若未来支持局域网多机模式，需重新评估本 ADR
