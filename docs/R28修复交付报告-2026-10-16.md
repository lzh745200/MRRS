## 4. 刻意不改 / 延后项（含理由）

1. **`utils/encryption.py` 整体读盘（R27 低危）** —— **延后，已就地写明**。
   `config.py` 与 `scripts/manage_keys.py` 只消费 `from_key_string`；`encrypt_file`/`decrypt_file`
   **全仓无生产调用方**，真正的数据包加解密路径是 `services/password_encryption_service`
   （格式 `salt|iterations|token`，与本模块「整文件 Fernet 令牌」不兼容）。改这两处只会改一个
   无消费方的格式：零收益，却可能破坏历史加密包可解性。已在类 docstring 写明前提条件
   （将来复用时必须先设计分块格式并迁移调用方）。
2. **限流器双实现**（`core/security.check_rate_limit` vs `services/resource_limiter`）——
   R27 §3 已登记为设计问题。M22（配额重建导致限流永不生效）与 M38（配置接线）均已修，
   双实现合并属重构（收益 < 回归风险），本轮不动，保留为后续架构项。
3. **`admin` 的 org-tree 全量口径**：`/dashboard/*`、`/map/*` 等大屏端点沿用
   `OrgScopeFilter`/`get_org_scope` 的既有「管理员全量」语义（与 `/dashboard/stats` 一致）；
   **导出与列表类**走 S2 严格口径（部门级 admin 仅本组织及子树）。两套口径的边界已在
   `core/data_permission.py` 与 `services/data_scope_query.py` 的 docstring 写明。
4. **三处 R20 遗留列类型（R27 §3 服务层）本轮仍不修**，因为都需要 Alembic 数据迁移 +
   存量数据回填，与「批量修复」混做会把发布风险从代码级抬到数据级：
   `models/rbac.py:207` `AccessLog.user_id = String(36)`（全仓其它 user_id 为 Integer）、
   `models/todo.py:34` `Todo.deadline = String(20)` 存日期、
   `models/two_factor_auth.py:23` `secret_key = String(255)` 明文（未迁 `EncryptedText`）。
   建议单独立项：`AccessLog.user_id` 需先确认历史行是否含非数字值（否则类型转换会失败），
   `TwoFactorAuth.secret_key` 迁移需要「读时兼容明文 / 写时加密」双轨期。
5. **只报告不改（超出本轮风险预算）**：`frontend/package.json` description 双重编码乱码与
   `scripts/scan_mojibake.py` 未接入 CI；`backend/requirements.txt` 无上界依赖。
