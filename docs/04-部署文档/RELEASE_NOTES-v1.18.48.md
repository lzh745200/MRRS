# v1.18.48 发布说明 — 机器码一次性恢复码与高风险操作二次确认（安全加固）

发布日期：2026-11-15
上一版本：v1.18.47

## 谁需要升级

- 所有已部署单位建议升级：本次修复了「机器码校验码可离线推导」与「高风险操作仅靠登录态即可执行」两处安全弱点。
- 仍在使用 v1.18.44 及更早版本、且现场反馈「登录页导入权限包 403」「换机后无法重置管理员密码」的机器，必须升级。

## 本次改动

### 1. 机器码一次性恢复码

- 原「4 位确定性校验码」可由机器码离线推导，等同于公开算法；现改为**服务端随机 8 位恢复码**：
  只保存 bcrypt 哈希、默认 10 分钟有效（60~1800 秒可配）、同一机器同一用途只保留一个
  （新码签发即作废旧码）、错误 5 次自动作废、消费为原子更新（并发只成功一次）。
- 新增 `machine_recovery_codes` 表（迁移 `machine_recovery_001`）。
- `GET /api/v1/machine-code/get-machine-code` 不再产生/返回任何校验码（避免页面预取反复作废旧码）；
  「获取机器码」「忘记密码」页在需要时调用 `POST /api/v1/machine-code/recovery-code`
  由本机签发并展示。
- 旧版 4 位校验码不再可用；已发出的恢复码一旦被新码覆盖即失效。

### 2. 高风险操作二次确认

以下操作必须额外携带当前登录用户的密码（`X-Confirm-Password` 请求头，不进入 URL 与日志）：

- 修改用户、删除用户、分配用户权限、管理员重置他人密码；
- 备份恢复、上传备份恢复；
- 权限包确认导入（仅已登录调用者；全新机器登录前的离线首装仍沿用本机回环 + 出厂态校验）。

行为约定：缺失密码 → **428** `REAUTH_REQUIRED`；密码错误 → **400**；同一用户 60 秒内失败 5 次 → **429**。
前端 axios 拦截器收到 428 后统一弹出密码框，确认后带密码自动重放一次，取消则保持原错误。
测试环境（`ENVIRONMENT=test/testing`）自动跳过；`CONFIRM_PASSWORD_ENFORCED=false` 可显式关闭（不建议生产使用）。

### 3. 密码与会话

- 初始密码、管理员重置密码改为服务端随机 16 位（排除易混字符）。
- 重置成功后调用 `revoke_all_tokens()`，该用户所有旧令牌立即失效，必须用新密码重新登录。

### 4. 权限包导入结果

- 目标机不存在的用户名不再静默跳过，返回 `partial` / `warnings` / `skipped_usernames`；
  登录页导入结果会明确提示「部分账号未创建，相关权限与菜单可能未生效，请由管理员补建账号」。

## 升级注意事项

1. 升级后旧「机器码校验码」立即失效；如现场保存过旧码，请重新获取恢复码。
2. 管理员重置密码、恢复备份等操作会要求再次输入当前密码，请提前告知操作人员。
3. 数据库迁移 `machine_recovery_001` 为新增表，可自动升级；升级前仍建议备份数据库。
4. 本次不改变数据包/授权包协议，跨版本导入导出保持兼容。

## 已知边界

- 恢复码只在本机回环（127.0.0.1）签发，远程无法直接获取；远程换机请联系管理员在管理端生成。
- 二次确认密码只防误操作与借用已登录会话的物理操作者，不替代账号权限本身。
- 自签名安装包仍需目标机信任证书（详见《代码签名》文档）。
