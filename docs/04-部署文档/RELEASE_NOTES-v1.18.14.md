# Release Notes — v1.18.14（2026-10-27）

> 供 GitHub Release 正文使用；逐项变更见仓库根目录 `CHANGELOG.md` 的 `[1.18.14]` 段。
> 本版是**组织编码口径的收口**：起因是你反馈「黔南州及各县市的行政区划代码是 522700」，
> 核实后确认**编码规律本身没错**（522700 黔南州；522701 都匀市 … 12 个县市各有独立代码），
> 但顺着这条线查出 **4 个真实缺陷**，全部修复。

## 二、编码规律核实结论（先说结论）

| 单位 | 代码 | 层级 | 是否符合 `XXYY00 / XXYYZZ` |
|---|---|---|---|
| 贵州省 | 520000 | 省级 | ✅ `XX0000` |
| 黔南布依族苗族自治州 | **522700** | 市州级 | ✅ `XXYY00`（52 省 / 27 州 / 00） |
| 都匀市 / 福泉市 | 522701 / 522702 | 县市级 | ✅ `XXYYZZ` |
| 荔波 / 贵定 / 瓮安 / 独山 | 522722 / 522723 / 522725 / 522726 | 县市级 | ✅ |
| 平塘 / 罗甸 / 长顺 / 龙里 | 522727 / 522728 / 522729 / 522730 | 县市级 | ✅ |
| 惠水 / 三都 | 522731 / 522732 | 县市级 | ✅ |

依据仓库内置的官方 adcode 数据核验：贵州 **9 个市州全部**判为市州级、**88 个县级单位全部**判为县市级。
**县市不要填 522700** —— 那是黔南州本级的代码。

## 三、修掉的 4 个真实缺陷

### P1（严重）初始化建根组织时，编码被随机替换

`system/init.py` 传入 `code=522700`，但 `OrganizationService.create_organization()` 内部调用
`generate_code()`，把传入的行政区划代码**整个丢弃**。实测：传 `522700` → 落库
**`ORG-848B7F7C`**、`level=1`。跨机匹配（编码是唯一依据）与组织树因此全错。

现已改为以传入编码为准、层级由代码推导；重复编码拒绝入库。

### P2（严重）初始化强制要求省级编码

`_resolve_root_org_code` 原先要求编码末四位为 `0000`。黔南州是市州级 → 首启**必然 400**
（「根组织必须是省级单位」），只能先造一个省本级根再手工建州。

现在**省 / 市州 / 县级都可作为首启单位**：直接以 522700 建根，县市挂在它下面；
县级单位作为根时不再允许建下级（业务只有三级）。

### P3（中）不校验代码是否真实存在

此前只按末位规律判层级 —— `522799`、`999999` 都能入库并被判成「县市级」。
现接入**权威行政区划表**：贵州省为全量校验，空号（如 522724）直接 422 拒绝；
表未覆盖的其它省份退回末位规律并标记「未校验」，不误杀。

### P4（中）不校验父子是否属于同一行政区划

此前只校验「子层级 = 父层级 + 1」，于是 `522701`（都匀市）可以挂到 `520100`（贵阳市）下 ——
组织树展示位错，且**按 path 前缀计算的数据权限会把黔南的县市算进贵阳子树**。
现在要求父子同属一个区划（表内条目用表里的 parent，表外条目按代码前缀），
错误信息会直接说明「522701 的上级应为 522700，而不是 520100」。

### P5（顺带修复）越权者可用响应差异探测别单位编码

`POST /organizations` 原先**先查编码重复、后判越权**，越权者可用 400 与其它响应的差异
反推其它分支的组织编码。现改为**越权 403 先行**。

## 四、新增能力

- **权威区划表** `backend/app/data/admin_divisions.json`（11 KB，随安装包分发）：
  省级 34 全量；贵州 9 市州 + 88 县级全量；`aliases` 存区划调整换码（520222 盘县 → 520281 盘州市）。
- **单一校验入口** `OrganizationCodeService.validate_admin_code(code, parent_code)`：
  格式 → 别名归一 → 存在性 → 父子同区划。落库路径（新增组织 / 系统初始化 / 服务层）全部走它。
- **缺表自动降级**：数据文件缺失或损坏时回落「末位规律」并写告警日志 —— 绝不会因为缺文件
  把合法编码判成非法（老安装包/裁剪包也能启动）。
- **Windows 打包修正**：`assistance-backend.spec` 原先漏收 `app/data`（两个 Linux spec 收的是整个
  `app`），会导致安装包内的编码校验找不到表；已显式收集。

## 六、升级注意

- **已有组织不会被改写**：本版只影响新建/初始化路径；历史上编码为 `ORG-XXXX` 的组织如需纠正，
  请停用后按正确行政区划代码新建（编码创建后不可修改）。
- 若你在**首次初始化时填的是 522700 却没生效**（落成了 `ORG-` 开头），这正是 P1：
  请用本版重建组织树（旧库数据可先导出备份）。
