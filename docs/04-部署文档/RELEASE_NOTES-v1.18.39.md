# v1.18.39 发布说明 — 深度审计收口（越权 / 恢复 / 导入 / 上传 / 构建）

发布日期：2026-11-07

## 谁需要升级

- **所有部署（强烈建议）**：本版修复一处“任意登录用户可批量硬删政策”的高危越权，
  以及政策附件 IDOR、导出草稿泄露、菜单/项目/报表订阅/经费记录跨组织等问题。
- **使用数据包 / 历史备份恢复的单位**：恢复失败不再无条件回滚、恢复后自动迁移；
  帮扶村导入补齐省/市/县/乡镇/经纬度字段，软删记录可复活。
- **使用批量操作的运维人员**：`work_logs` 等无组织列的表按本人记录收窄，缺身份直接拒绝。
- **使用自签名安装包的 Windows 单位**：签名与信任方式不变（见文末）。

## 本版改动

### 1. 安全（越权 / 注入）

- 政策批量删除：改为逐条写权限校验 + 软删除，并同步全文索引、工作日志与变更审批。
- 政策附件预览/下载：补可见性校验（管理员 / 启用 / 作者），修复 IDOR。
- 政策导出：非管理员仅导出启用且“启用状态或本人创建”的记录，草稿与软删不再泄露。
- 政策列表 `limit` 上限 200；政策分类维护仅管理员。
- 全局搜索：非管理员过滤软删与他人草稿。
- 菜单配置：部门级 admin 仅能改本组织子树用户，且不得裁剪 `super_admin`。
- 项目创建：`village_id` 经数据域校验，越权返回 404。
- 权限包导入：非超管禁止 mirror 覆盖；被写用户须在调用者子树内、不得改自己、清除通配权限。
- `data_scope="self"`：`require_data_permission` 按 OWN 判定，修复同组织越权读/删。
- 报表订阅 `output_dir`：必须落在系统上传目录内，否则 400。
- 经费独立记录：部门级 admin 仅可读写本组织子树（14 处端点统一）。
- 批量操作：无组织列的表按本人 `user_id` 收窄，缺身份 fail-closed。
- 上传：文件名去尾点/空格、必须带扩展名并命中白名单、MIME 由服务端判定、
  经费附件预览 inline 白名单收窄、iframe 加 `sandbox`。
- CI：tag 名经 `env` 传参并加引号、`sync-version` 版本号严格正则，消除 tag 注入面。
- CSRF：豁免前缀改路径边界匹配；内部备份密钥仅对备份/停机路径生效，其余路径仍双提交校验并记 warning。

### 2. 数据正确性（恢复 / 导入 / 同步）

- 备份恢复：仅在数据库已替换后才回滚；回滚前 dispose 并清理 `-wal/-shm`。
- 帮扶村导入：补齐省份/州市/县市/乡镇/经纬度/转型字段；`prefecture`→`city`；
  同名软删记录复活并更新，按 ID 回导同样复活。
- 数据包导入：组级写入有失败即整体回滚并返回失败，不再“部分成功”。
- 注册自验证：单位不存在时不再自动创建组织（返回失败并记 warning）。
- 每日数据库维护：读取 `PRAGMA integrity_check`，非 `ok` 写 ERROR 日志。
- 孤儿附件清理：只查 `attachment_urls` 列，避免整表加载政策正文。
- 填报模板导出：以 `= + - @` 开头的文本强制按文本单元格写入，防 Excel/WPS 公式注入。
- 数据包导入：datetime 解析改为严格 ISO 前缀匹配，含字母 T 的普通文本不再被误转。

### 3. 审计结论

- 审计覆盖 API / services / core / 前端构建链，发现 **1 个 P0、7 个 P1 与若干 P2**；P0/P1 全部修复，
  P2 中可安全修复的已修，其余作为已知边界在下方列明。
- `bandit -ll`：0 条 medium/high。
- `check_route_auth`：854 条路由，58 条未鉴权端点全部在公开白名单内。
- MD5/SHA1 均带 `usedforsecurity=False`（缓存键/机器码/分块校验），非安全用途。
- 导出注入转义、`v-html` 消毒、ZIP 防穿越、Electron 隔离与 IPC 白名单均已就位。

### 4. 已知边界（本轮不改行为）

- 数据包 `confirm_import` 不复算 `data_checksums`（文件在服务器侧，需本机文件被替换才可利用）。
- 通行码内置回退密钥沿用 2026-09-06 产品决策（未配置 `PASS_CODE_SECRET` 时保证跨机注册可用）。
- 极老备份（无 `alembic_version` 但有业务表）按启动同口径 `stamp head`；
  旧库缺后续列时不会被历史迁移补齐。
- 未激活账号登录返回明确 403「账户尚未激活」，属自助注册 UX 选择，存在账号存在性提示，
  但不返回密码相关差异。

## 安装与信任（重要）

自签名不是公共 CA 证书，**未信任根证书的机器上签名状态会显示为 UnknownError / NotTrusted**，
这是预期行为，不影响程序运行；按下列任一方式信任后可显示为 Valid：

1. **域环境（推荐）**：用 GPO 把 `MRRS-Internal-CodeSigning.cer` 下发到
   「受信任的根证书颁发机构」与「受信任的发布者」。
2. **单机（管理员 PowerShell）**：
   ```powershell
   certutil -addstore -f Root MRRS-Internal-CodeSigning.cer
   certutil -addstore -f TrustedPublisher MRRS-Internal-CodeSigning.cer
   ```
3. **核验签名**：
   ```powershell
   Get-AuthenticodeSignature .\MRRS-Setup-1.18.39-x64.exe | Format-List Status, StatusMessage, SignerCertificate
   ```
   签名者应为 `CN=MRRS Internal Code Signing, O=MRRS, C=CN`，指纹
   `8203900B6DA54201A49BDAF923B2F20D76CA35A1`，有效期至 2031-11-05。
