# 离线加固与运维开关（v1.18.0）

> 本文件记录 v1.18.0 引入的**离线相关开关、路径规则、备份恢复行为与构建脚本**。
> 面向：现场实施、运维、二次开发。

---

## 一、环境变量开关

| 变量 | 默认 | 作用 | 注意 |
|---|---|---|---|
| `OFFLINE_MODE` | `true` | 为真时**邮件告警 / Webhook 告警两通道入口直接短路**（不解析配置、不做 DNS/连接） | 需要外呼（如接内网邮件网关）必须显式设 `OFFLINE_MODE=false` |
| `BUMOFU_DATA_DIR` | 空 | Linux / 打包态**数据根目录**（数据库、上传、备份、缓存、运行密钥） | 优先级最高；麒麟部署由 `kylin.env` 设为 `/var/lib/assistance-management-system` |
| `XDG_DATA_HOME` | 空 | 未设 `BUMOFU_DATA_DIR` 时的次选：`$XDG_DATA_HOME/bumofu` | 再回退 `~/.local/share/bumofu`（**不再使用** `~/.bumofu`） |
| `BACKUP_DIR` | 空 | 备份目录，**优先于** `<数据根>/backups`；不校验/不创建（首次写入时创建） | 用于把备份放到独立磁盘/U 盘 |
| `INCLUDE_MAP_TILES` | 空（关） | 构建期开关：`=1` 时 PyInstaller 把 `resources/map-tiles` 打进后端产物 | **默认关**：Electron 版由 extraResources + `MAP_TILES_DIR` 提供瓦片，避免安装包多 ~60MB；仅"无 Electron 的 standalone 后端"需要打开 |
| `MAP_TILES_DIR` | 空 | 运行期瓦片目录（Electron 注入 `<resources>/map-tiles`） | 优先级最高，见 `app/api/v1/map.py` |

> Windows 桌面版路径语义**未变**：数据仍在 `%LOCALAPPDATA%\bumofu-assistance`（Electron 另注入
> `DATABASE_URL/UPLOAD_DIR/...` 到 userData）。本批只改 Linux/打包态。

## 二、`/health` 新增只读块（v1.18.0）

```json
{
  "status": "ok",
  "clock":    { "status": "ok|warning|unknown", "behind_days": 0.0 },
  "database": { "journal_mode": "wal|delete|unknown", "journal_mode_ok": true, "check_error_type": null }
}
```

- `clock.status=warning`：系统时钟落后数据最新记录 > 1 天（离线机常被手动改时间）。
  带 120s TTL 缓存，不返回异常原文（`/health` 无认证）。
- `database.journal_mode_ok=false`：SQLite 未进入 WAL（常见于网络盘/OneDrive/只读卷）→ 并发读写退化、
  易 `database is locked`。**不阻断启动**，仅告警。
- 顶层 `status` 与 HTTP 状态码保持原语义（不因这两个块变红）。

## 三、备份与恢复（v1.18.0 行为变化）

1. **备份包内新增 `key_fingerprint`**（`backup_info.json`，SHA256 前 16 位；不含密钥本体）。
2. **恢复时校验**：备份指纹 ≠ 本机指纹 → **409**，提示"备份来自不同密钥的机器，恢复后敏感字段将不可读"；
   - 确实要用旧密钥恢复：`allow_key_mismatch=true`（API 参数 / 上传恢复表单字段），会写审计
     `system_restore_key_mismatch`（拒绝=CRITICAL、强制=WARNING）。
   - 旧备份无该字段、包内无 `backup_info.json`、或本机指纹不可用 → **兼容放行**（不锁死恢复通道）。
3. **历史格式兼容**：旧全量包 `backup_info.json` 曾用 `str(dict)` 写出非法 JSON，已用
   `json.loads → ast.literal_eval` 双解析兼容。
4. **启动补跑**：启动 15 秒后若"从未备份或距上次超过 `backup_interval_days`"→ 立即补跑一次；
   补跑成功后当日 02:00 的日常备份自然跳过（幂等）。用于"夜间关机导致自动备份长期不执行"的现场。

## 四、Windows 构建（v1.18.0）

本机实测两个坑及对应脚本：

```powershell
# 一键：前端构建 → 同步 resources/frontend → PyInstaller → NSIS
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build-win.ps1

# 只同步（bash 被 WSL 占用时的替代）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/sync-frontend.ps1

# 可选：把瓦片也打进后端（仅 standalone 后端分发）
powershell -File scripts/build/build-win.ps1 -IncludeMapTilesInBackend
```

- 脚本自动把 `TEMP/TMP` 重定向到 `.scratch/tmp`，规避默认 `%TEMP%` 下 esbuild `Access is denied`。
- `scripts/build/sync-frontend-dist.sh`（bash）在 Windows 上可能因 WSL 损坏而不可用；PowerShell 版为等价实现
  （robocopy /MIR + 文件数/字节数/index.html 校验）。

## 五、升级注意（从 1.17.x 升到 1.18.0）

- **Windows**：路径/缓存/备份位置均未变，直接覆盖安装即可。
- **Linux 非打包且未设 `BUMOFU_DATA_DIR`/`XDG_DATA_HOME`**：默认数据根由 `~/.bumofu` 变为
  `~/.local/share/bumofu`。**旧数据不会自动迁移**；若要沿用旧目录，请设 `BUMOFU_DATA_DIR=~/.bumofu`
  或手工搬迁（数据库/上传/备份/`runtime_secrets.json` 需一起搬，否则 PII 密文不可解）。
- **麒麟 standalone**：`kylin.env` 已显式指向 `/var/lib/assistance-management-system`，无数据搬迁；
  `dpkg -i` 升级会幂等修正服务用户 HOME 与目录权限。
- **外呼告警**：升级后默认 `OFFLINE_MODE=true`，若现场依赖邮件/Webhook，请显式设 `OFFLINE_MODE=false`。
