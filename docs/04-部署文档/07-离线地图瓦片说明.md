# 离线地图瓦片说明（安装包自带 + 资产化流程）

> 适用版本：v1.18.44 起（此前 CI 产出的安装包不含离线瓦片，地图页只能显示兜底提示）。
> 对象：交付/运维（验包、补瓦片）、构建（改瓦片版本）、开发（本地地图调试）。

## 1. 为什么瓦片不在 git 里

`resources/map-tiles/` 是 5,625 张 PNG（z5–z12，贵州范围），约 **60MB**。瓦片体积大且可由
`scripts/tiles/` 下的脚本从 GeoJSON 重新生成，因此 `.gitignore` 排除了 `resources/map-tiles/**/*.png`
与 `MANIFEST.json`，仓库只保留占位说明。

后果：**CI 构建机取不到瓦片**——v1.18.43 及更早的 Release 安装包装完后地图页空白。v1.18.44 起改为
「固定资产 + 构建期拉取」：瓦片打包成 `map-tiles-v1.zip` 发布在专用 Release
[`tiles-v1`](https://github.com/lzh745200/MRRS/releases/tag/tiles-v1)，三条构建链在打包前下载并校验
SHA256 后解压到 `resources/map-tiles`，再由打包配置收进安装包。

## 2. 固定资产（唯一来源）

| 项目 | 值 |
| --- | --- |
| Release | `tiles-v1`（不是 latest，不会被「最新版本」链接指向） |
| 资产 | `map-tiles-v1.zip`（5,625 文件，ZIP_STORED，约 63,524,922 B） |
| SHA256 | `2b66baec5f041996d79afe58c0aea95bf7ce086555ff6a8163261cee5c45edbe` |
| 授权 | © OpenStreetMap contributors，ODbL-1.0；安装包与文档必须保留该署名 |

该 SHA256 在三个构建步骤里**钉死**（`build-windows.yml` 的 `Fetch offline map tiles`、
`build-arm64.yml` 的 Electron 作业与 standalone 作业各一处）。换瓦片版本时必须同步改这三处，
否则构建会在 `sha256sum -c` / `Get-FileHash` 处直接失败——这是有意的：宁可构建红，不发缺瓦片的包。

## 3. 三条构建链如何拿到瓦片

| 产物 | 步骤 | 瓦片落点 |
| --- | --- | --- |
| Windows x64 安装包 | `build-windows.yml` → `Fetch offline map tiles`（PyInstaller 之后） | `resources/map-tiles` → electron-builder `extraResources` → `<安装目录>/resources/map-tiles` |
| ARM64 Electron DEB | `build-arm64.yml`（Electron 作业）→ `Fetch offline map tiles` | 同上 |
| ARM64 standalone DEB（无 Electron） | `build-arm64.yml`（standalone 作业）→ `Fetch offline map tiles` → `docker build` | `docker/Dockerfile.kylin-standalone` 的 `COPY resources/map-tiles/` → PyInstaller spec 收进 `_internal/resources/map-tiles` |

拉取后都会执行 `python scripts/tiles/verify_tiles.py --require-min 5000 --sample 20`：
少于 5,000 张或 PNG 抽样损坏即失败。

## 4. 收到安装包后怎么验（交付/运维）

Windows（管理员 PowerShell）：

```powershell
$root = "C:\Program Files\MRRS"          # 实际安装目录以安装器为准
(Get-ChildItem "$root\resources\map-tiles" -Recurse -Filter *.png).Count   # 期望 ≈ 5625
Test-Path "$root\resources\map-tiles\MANIFEST.json"                        # 期望 True
```

麒麟 / ARM64 DEB：

```bash
dpkg -L assistance-management-system | grep map-tiles | head
find /opt/assistance-management-system -path '*map-tiles*' -name '*.png' | wc -l
```

应用内：打开「地图」页，离线状态下应能看到贵州底图；在线地图不可用属预期（本系统完全离线）。
后端直连自检（需登录令牌）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' "http://127.0.0.1:8000/api/v1/map/tiles/8/207/105.png"
# 200 = 命中；404 = 该瓦片不存在；503 = 瓦片目录缺失（说明包没带瓦片）
```

## 5. 手工补瓦片（不重装）

1. 下载固定资产：`gh release download tiles-v1 --pattern map-tiles-v1.zip`；
2. 校验：`sha256sum -c`（值见上表）；
3. 解压覆盖到安装目录：
   - Windows：`Expand-Archive map-tiles-v1.zip -DestinationPath "<安装目录>\resources\map-tiles" -Force`
   - Linux：`unzip -o map-tiles-v1.zip -d /opt/assistance-management-system/resources/map-tiles`
4. 重启应用（Electron 启动时读取 `MAP_TILES_DIR`）。

## 6. 瓦片版本升级流程（构建/发布）

1. 重新生成或替换 `resources/map-tiles/`（`python scripts/tiles/verify_tiles.py --require-min 5000` 先自检）；
2. 打新 zip：`python -c "import shutil;shutil.make_archive('map-tiles-v2','zip','resources/map-tiles')"`；
3. `gh release create tiles-v2 map-tiles-v2.zip --latest=false`；
4. 计算 sha256，更新三个 workflow 里的 `TILES_ASSET_SHA256` 与 `tiles-v1` → `tiles-v2`；
5. 跑一次 tag 构建，确认安装包体积增大约 60MB 且包内 `resources/map-tiles` 文件数 ≈ 5,625。

## 7. 常见问题

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 构建日志 `tiles zip sha256 mismatch` | 资产被替换/截断，或 `TILES_ASSET_SHA256` 未同步 | 重新下载并核对 Release 资产大小，或按第 6 节换版本号 |
| 构建日志 `--require-min 5000` 失败 | 解压不完整 / 资产本身缺瓦片 | 清缓存重跑；仍失败则重新生成资产 |
| 装机后地图页只有占位提示 | 安装包未带瓦片（多见于 v1.18.43 及更早） | 按第 5 节手工补，或升级到 v1.18.44+ |
| 地图页显示「瓦片不可用」诊断 | 瓦片目录缺失或 `MAP_TILES_DIR` 指向错误 | 检查 `resources/map-tiles` 与启动参数 |
