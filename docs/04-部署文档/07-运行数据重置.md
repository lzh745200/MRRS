# 运行数据重置（清空业务数据并重建空系统）

> 适用版本：v1.18.39 及以后。**高危操作**：会删除本机数据库、上传附件、备份与日志。
> 仅用于交付前清空演示数据、或在确认已归档后重建空库；生产环境请先完整备份。

## 1. 它做什么

`scripts/reset_system_data.py` 会：

1. 把实际运行目录（`settings.DATABASE_URL` / `UPLOAD_DIR` / 备份目录，以及工作区根下
   历史遗留的 `data/`、`uploads/`、`backups/`、`data_sync/`、`logs/`）打包到
   `.pre-clean-archive/<时间戳>/mrrs-runtime-data.zip`；
2. 保留所有 `runtime_secrets.json`（PII / 备份加密密钥）——否则归档备份将无法解密；
3. 删除数据库、附件、备份、同步包与日志（不碰代码、`.env`、`dist/`、`node_modules/`）；
4. 之后首次启动由应用自动建库、迁移、播种默认管理员（需要重新设置密码）。

## 2. 用法

```bash
# 先确认当前生效库（脚本以 settings 解析结果为准）
cd backend
.venv/Scripts/python.exe -c "from app.core.config import settings; print(settings.DATABASE_URL)"

# 归档 + 清空（必须显式 --yes，否则只打印将要操作的内容并退出）
cd ..
backend/.venv/Scripts/python.exe scripts/reset_system_data.py --yes
```

## 3. 注意

- 归档 ZIP 默认留在仓库根 `.pre-clean-archive/`，请先复制到介质再清理该目录；
- 归档内含加密后的 PII 与备份，**按涉密介质管理**；
- 若 `DATABASE_URL` 不是 SQLite，脚本直接退出（本应用只支持 SQLite）；
- 若某个运行目录位于仓库之外（例如安装版 `%LOCALAPPDATA%`），脚本会拒绝执行并在
  控制台说明原因，请改用手工迁移/清理流程。
