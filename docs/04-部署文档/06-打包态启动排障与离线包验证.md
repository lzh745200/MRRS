# 打包态启动排障与离线安装包验证（v1.18.31+）

本文解决一类**只在安装包/冻结后端里出现、源码运行复现不了**的问题：双击图标后
后端起不来、进程反复重启后退出、黑屏/502。所有命令都在仓库根目录执行（Windows 用
`backend\.venv\Scripts\python.exe`，Linux 用 `backend/.venv/bin/python`）。

> 适用版本：v1.18.31 起（difflib 事故修复 + `verify_frozen_modules.py` 门禁接入之后）。
> 更早的 v1.18.29 ARM64 包**必然启动失败**，请直接升级，不要现场排查。

---

## 1. 三种安装包与它们把文件放在哪

| 形态 | 产物 | 后端可执行文件 | 数据/日志根目录 |
|---|---|---|---|
| Windows x64 桌面版（NSIS） | `MRRS-Setup-<版本>-x64.exe` | `resources\backend\assistance-backend\assistance-backend.exe` | `%LOCALAPPDATA%\bumofu-assistance\data\` |
| 麒麟 V10 ARM64 桌面版（deb） | `MRRS-Setup-<版本>-arm64.deb` | `/opt/帮扶管理系统/resources/backend/assistance-backend/assistance-backend` | `~/.bumofu/data/` |
| 麒麟 V10 ARM64 纯 Web 版（deb） | `assistance-management-system_<版本>_arm64.deb` | `/opt/assistance-management-system/`（systemd 托管） | `/opt/assistance-management-system/data/` |

**注意**：桌面版的冻结后端比库里多一层目录（`resources/backend/assistance-backend/`）。
`verify_frozen_modules.py --backend-dir` 必须指向**含 `assistance-backend.exe` 的那一层**，
指到 `resources/backend` 会报"找不到可执行文件"。

日志位置（排查先看这两个）：

- 后端业务日志：`<数据根目录>\logs\app.log`
- Electron 崩溃/后端 stderr：`<数据根目录>\logs\backend-crash.log`、`logs\diagnostics.log`

## 2. 已知的三个启动失败根因

### 2.1 `ModuleNotFoundError: No module named 'difflib'`（v1.18.29 ARM64 事故，已修）

- **症状**：安装后双击无界面；进程起 3 次后退出；`app.log` 末尾是
  `ModuleNotFoundError: No module named 'difflib'`。
- **根因**：`backend/backend_linux_arm64_standalone.spec` 曾把 `difflib` 放进
  `excludes`，而 `backend/app/services/data_cleaning_service.py` 是**顶层**
  `from difflib import SequenceMatcher` —— 冻结时模块被剔除，运行期 import 直接崩。
  源码运行不受影响，所以单元测试/本地启动全绿，只有打包后的产物会炸。
- **修复**（提交 `7fb5e910`）：
  - standalone spec 不再排除任何标准库，`difflib` 进 `hiddenimports`；
  - `backend/assistance-backend.spec` 显式列 `difflib`；
  - 新增 `scripts/verify_frozen_modules.py`，在 Windows / ARM64 Electron / standalone /
    deb 四条链路里**构建期**校验冻结模块表；
  - `backend/start.py` 增加 `BACKEND_IMPORT_CHECK=1` 自检入口（只 import，不启 HTTP）。
- **防复发规则**：spec 的 `excludes` 里**禁止出现任何标准库模块**；新增/删除顶层
  标准库 import 后必须跑 §3 的模块自检。

### 2.2 手工启动冻结后端时环境变量缺失

冻结后端**不会**像 Electron 那样自动注入数据库路径与密钥。直接双击 exe 或在
cmd 里裸跑，会因 `DATABASE_URL` 落到当前目录、`ENCRYPTION_KEY` 为空而出现：
数据库建错位置、PII 列解密失败、`SECRET_KEY` 每次重启都变（登录态全掉）。

完整环境变量见 §4 表格。**桌面版安装后不需要手工配置**，这些值由
`electron/main.js` 的 `getOrCreateSecrets()` 与 `startBackend()` 注入并持久化到
`secrets.json`（`safeStorage` 加密）。

`PASS_CODE_SECRET` 是唯一需要**运维手工统一**的可选项：未配置时，来自非回环来源的
自助注册会被 fail-closed 拒绝（403），单机桌面开箱不受影响。多机/LAN 部署必须
在**所有实例**配置同一个随机值（Windows：系统环境变量；Linux：`config/kylin.env`）。
Electron 会把 `process.env` 原样传给后端，所以设成系统环境变量即可生效。

### 2.3 PII 密钥变化导致历史数据解密失败

`ENCRYPTION_KEY` 一旦变化，`households.helper_phone` 等 9 个加密列的旧密文无法解密。
桌面版把它存在 `secrets.json`，**不要删除该文件**；迁移机器时要么整体拷贝数据目录，
要么显式配置同一个 `ENCRYPTION_KEY`。症状是页面报 `PII 解密失败` 或字段显示为空。

## 3. 冻结模块自检（打包后必跑）

```powershell
# Windows：指向安装包解包后的内层目录
backend\.venv\Scripts\python.exe scripts\verify_frozen_modules.py `
  --backend-dir "dist\electron\win-unpacked\resources\backend\assistance-backend"
```

```bash
# Linux（deb 解包或 /opt 下同一布局）
backend/.venv/bin/python scripts/verify_frozen_modules.py \
  --backend-dir /opt/assistance-management-system/assistance-backend
```

通过时输出（v1.18.31 实测）：

```
[INFO] PYZ 模块数：4598
[INFO] 校验模块数：384
[OK] difflib
[OK] app.main
[OK] app.services.data_cleaning_service
[OK] app.* 模块全部收录（379 个）
FROZEN_MODULE_CHECK_PASS
```

退出码非 0 即视为构建失败，**不得发布**。CI 已把它接到两个构建工作流里，
本地只有在手工打包/替换后端时才需要单独跑。

## 4. 打包后端冒烟（不起 Electron，直接验后端）

最小可用环境变量（Windows PowerShell，实测 v1.18.31）：

| 变量 | 作用 | 桌面版默认 |
|---|---|---|
| `DATABASE_URL` | SQLite 连接串 | `sqlite:///<数据目录>\database\rural_revitalization.db` |
| `HOST` / `PORT` | 监听地址 | `127.0.0.1` / 动态端口 |
| `LOG_FILE` | 业务日志落盘 | `<数据目录>\logs\app.log` |
| `UPLOAD_DIR` / `CACHE_DIR` / `EXPORT_DIR` | 上传/缓存/导出目录 | 数据目录下同名子目录 |
| `FRONTEND_DIST_PATH` | 前端静态资源 | 包内 `resources/frontend` |
| `MAP_TILES_DIR` | 离线瓦片 | 包内 `resources/tiles` |
| `ENVIRONMENT` | 固定 `production` | `production` |
| `PROJECT_VERSION` | `/version.json` 版本号 | 安装包版本 |
| `SECRET_KEY` / `CSRF_SECRET_KEY` | JWT / CSRF 签名 | secrets.json（自动生成） |
| `ENCRYPTION_KEY` | PII 加密（AES-SIV） | secrets.json（自动生成） |
| `INTERNAL_BACKUP_KEY` / `INTERNAL_SHUTDOWN_KEY` | 内部接口鉴权 | 每次启动随机 |
| `PASS_CODE_SECRET` | 跨机通行码 HMAC | 空（见 §2.2） |
| `ENABLE_AUTO_MIGRATION` | 冒烟时建议 `false` | 未设置 |

```powershell
$root = "dist\electron\win-unpacked\resources\backend\assistance-backend"
$data = "$PWD\.scratch\smoke-data"
$env:DATABASE_URL   = "sqlite:///$data\rural_revitalization.db"
$env:HOST="127.0.0.1"; $env:PORT="18124"; $env:ENVIRONMENT="production"
$env:LOG_FILE="$data\logs\app.log"; $env:UPLOAD_DIR="$data\uploads"
$env:CACHE_DIR="$data\cache"; $env:EXPORT_DIR="$data\exports"
$env:ENCRYPTION_KEY=[Convert]::ToBase64String((1..32 | %{Get-Random -Max 256}))
$env:INTERNAL_BACKUP_KEY="smoke-backup-key"; $env:INTERNAL_SHUTDOWN_KEY="smoke-shutdown-key"
& "$root\assistance-backend.exe"
```

启动成功判据（另一终端）：

```powershell
Invoke-RestMethod http://127.0.0.1:18124/api/v1/health/liveness   # {"status":"alive"}
Invoke-RestMethod http://127.0.0.1:18124/api/v1/health            # status=healthy + uptime_seconds
Invoke-RestMethod http://127.0.0.1:18124/version.json             # 版本号与安装包一致
```

v1.18.31 实测：**18 秒内 liveness 返回 200**，`/api/v1/health` 返回
`{"status":"healthy","uptime_seconds":15.0,"cpu_count":12}`，`/version.json` 返回
`{"version":"1.18.31","buildTime":"2026-10-31T15:25:39.390Z"}`；日志含
`Application startup complete`、`PII 加密密钥已从 ENCRYPTION_KEY 派生`、19 个索引创建成功、
14 个调度器启动。stderr 只有 `PASS_CODE_SECRET 未配置` 这一条警告（属预期，见 §2.2）。

## 5. 症状 → 处置速查

| 症状 | 先看哪里 | 处置 |
|---|---|---|
| 双击后闪退/无窗口 | `logs\backend-crash.log` | 有 `ModuleNotFoundError` → 按 §2.1 重打；模块缺失即构建缺陷，不是环境问题 |
| 窗口能开但页面 502/空白 | `logs\app.log`、`logs\diagnostics.log` | 后端未监听：端口被占 / 启动即崩；先按 §4 手工起后端看完整报错 |
| 页面提示"服务器未配置 PASS_CODE_SECRET" | 后端 stderr | 多机部署才需要：全实例配置同一 `PASS_CODE_SECRET` 后重启 |
| PII 字段为空/解密失败 | `app.log` 的 `pii_crypto` 行 | `ENCRYPTION_KEY` 变了：恢复原 `secrets.json` 或原密钥，勿重装覆盖 |
| 登录态反复失效 | 无 | `SECRET_KEY` 每次变化：确认 `secrets.json` 所在目录可写 |
| 安装包体积异常小（< 100 MB） | `dist/electron/` | 构建未完成或被杀；重新构建并核对体积与 `SHA256SUMS` |
