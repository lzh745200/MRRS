# Windows 安装器报“Error writing temporary file”排查与修复

> 现象：双击 `MRRS-Setup-1.18.35-x64.exe` 后，尚未进入安装向导即弹：
>
> `NSIS Error: Error writing temporary file. Make sure your temp folder is valid.`
>
> 这不是应用代码/后端启动错误，而是 NSIS 安装器在解压自身插件时写临时目录失败。

## 1. 根本原因

NSIS 安装器启动后会执行 `InitPluginsDir`，把插件解压到 `$TEMP`（Windows 的 `%TEMP%`）。`$TEMP` 是 NSIS 的**只读变量**，安装脚本内不能赋值；如果它指向以下任一状态，安装器会在执行任何自定义安装逻辑前直接失败：

1. `%TEMP%` 指向已删除的目录或已拔出的外接盘（例如 `D:\Temp`、移动硬盘）；
2. Windows 清理工具/安全软件删除了 `%TEMP%` 目录，但没有重建；
3. `%TEMP%` 目录 ACL 拒绝当前用户或管理员写入；
4. `%TEMP%` 路径过长、包含异常字符，或所在磁盘只读/已满；
5. 安全软件（Defender Controlled Folder Access、360、火绒等）拦截安装器解压；
6. 以非管理员上下文运行 per-machine 安装器，且 `%TEMP%` 位于受保护目录。

> 关键点：错误发生在 `InitPluginsDir`，此时 electron-builder 的 `customInstall` 尚未执行；应用层日志、数据库、后端都不会留下记录。

## 2. 先诊断（只读，不改环境）

在 PowerShell 中执行：

```powershell
Write-Host "TEMP=$env:TEMP"
Write-Host "TMP =$env:TMP"
Test-Path -LiteralPath $env:TEMP
Get-Item -LiteralPath $env:TEMP -ErrorAction SilentlyContinue | Select-Object FullName, Attributes
Get-Acl -LiteralPath $env:TEMP | Format-List
Get-PSDrive -Name C | Select-Object Used, Free
```

也可以直接用仓库脚本的仅诊断模式（会自动定位最新安装器）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\windows\install-mrrs-with-clean-temp.ps1 -NoLaunch
```

正常输出应包含：

```
Current TEMP writable: True
Using temp directory: C:\Users\<用户>\AppData\Local\Temp
```

## 3. 立即修复（推荐，不改安装包）

用仓库脚本在**父进程**设置可写 TEMP/TMP，再启动安装器。子进程会继承正确环境，这是针对根因的修复，而不是改安装包内容：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\windows\install-mrrs-with-clean-temp.ps1
```

脚本逻辑：

1. 探测当前 `%TEMP%` 是否真实存在且可写（写入并删除一个 probe 文件）；
2. 不可写时依次回退到 `%USERPROFILE%\AppData\Local\Temp`、`%WINDIR%\Temp`；
3. 只对当前进程/子进程设置 `TEMP`、`TMP`，启动 `MRRS-Setup-*.exe` 并等待退出码；
4. 可用 `-Installer "完整路径"` 指定安装器；
5. 可用 `-TempDir "D://MRRS-Temp"` 显式指定一个已验证可写的目录（企业镜像/策略环境）；
6. 可用 `-Persist` 把 TEMP/TMP 写入当前用户环境变量（已打开的 Explorer 不会刷新，需注销/重启或从新终端启动安装器）。

手动等价命令（不跑脚本）：

```powershell
$temp = Join-Path $env:USERPROFILE 'AppData\Local\Temp'
New-Item -ItemType Directory -Path $temp -Force | Out-Null
$env:TEMP = $temp
$env:TMP  = $temp
& 'C:\path\to\MRRS-Setup-1.18.35-x64.exe'
```

> 不要直接在“设置 → 环境变量”里把 TEMP 指到不存在的外接盘；也不要依赖已打开的资源管理器刷新环境。

## 4. 永久修复（部署机器）

按顺序处理：

1. **重建目录**：`New-Item -ItemType Directory -Path "$env:USERPROFILE\AppData\Local\Temp" -Force`；
2. **修正用户环境变量**（需要新登录会话生效）：
   ```powershell
   setx TEMP "%USERPROFILE%\AppData\Local\Temp"
   setx TMP  "%USERPROFILE%\AppData\Local\Temp"
   ```
3. **检查 ACL**：`icacls "%USERPROFILE%\AppData\Local\Temp"`，当前用户/Administrators 应有修改/写入权限；
4. **检查磁盘**：系统盘至少保留数 GB；`Get-PSDrive C` 的 `Free` 不能接近 0；
5. **安全软件**：将 `MRRS-Setup-*.exe` 与 `%USERPROFILE%\AppData\Local\Temp` 加入白名单，或临时关闭 Controlled Folder Access 后重试；
6. **路径长度**：避免把 TEMP 指到超过 200 字符的深层目录；
7. **静默安装**：企业部署可用 `MRRS-Setup-*.exe /S`，但必须先确保 `%TEMP%` 可写，否则 NSIS 仍会在进入静默安装前失败。

## 5. 验证修复是否真正生效

### 5.1 临时目录探测

```powershell
$probe = Join-Path $env:TEMP ("mrrs-probe-{0}.tmp" -f [guid]::NewGuid())
try {
  Set-Content -LiteralPath $probe -Value ok -ErrorAction Stop
  Write-Host "TEMP writable: True"
  Remove-Item -LiteralPath $probe -Force
} catch { Write-Host "TEMP writable: False: $($_.Exception.Message)" }
```

### 5.2 安装器闭环

1. 运行 `install-mrrs-with-clean-temp.ps1`（或手动设置 TEMP 后启动安装器）；
2. 安装向导应能正常进入，不再出现 `Error writing temporary file`；
3. 安装完成后启动“帮扶管理系统”，确认：
   - 登录页正常加载；
   - 版本号与安装包一致（1.18.35）；
   - 原有数据库/上传文件可见（若升级安装）；
4. 查看安装器退出码：脚本会输出 `Installer exit code: 0`；非 0 时按提示排查；
5. 打开 `%TEMP%`，确认安装器退出后 `ns*.tmp`/`$PLUGINSDIR` 临时目录可被清理（未被安全软件锁死）。

### 5.3 回归检查

- 该方案不修改安装包内容、不改 NSIS 打包配置，已有 `MRRS-Setup-1.18.35-x64.exe` 可直接使用；
- 若用 `-Persist`，确认新开终端里 `$env:TEMP` 指向新目录，且其他安装器/程序临时文件正常；
- 安装后建议重新运行一次 `scripts\verify_installer_payload.py`（发布物校验）或核对 `SHA256SUMS-windows-x64.txt`，确认使用的安装包未被篡改。

## 6. 为什么不在安装器脚本里直接改 `$TEMP`

`$TEMP` 是 NSIS 只读变量，`StrCpy $TEMP ...` 会编译失败；在 `preInit` 里重启自身并用批处理设置环境虽可行，但会引入重入/静默安装/参数转发风险，已在最小安装器上验证会挂起，因此不进入正式包。正确边界是：

- **NSIS 负责安装**，不负责修复操作系统临时目录；
- **启动包装脚本负责准备环境**，再交给 NSIS；
- 部署文档负责给出可复现的永久修复步骤。
