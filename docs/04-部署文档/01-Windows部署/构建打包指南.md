# Windows 构建打包指南

> 帮扶管理信息系统 — Windows 安装程序构建指南

本文档说明如何从源码构建 Windows `.exe` 安装程序，包含 x64 和 x86 两个架构。

---

## 构建概览

整体构建流程：

```
源码 → PyInstaller 打包后端 → electron-builder 打包前端+Electron壳 → NSIS 安装程序
```

| 组件 | 工具 | 产物 |
|------|------|------|
| 后端 (Python) | PyInstaller | `backend/dist/` 下的独立 `.exe` |
| 前端 (Vue 3) | Vite build | `resources/frontend/` 静态文件 |
| 桌面壳 (Electron) | electron-builder | NSIS 安装程序 `.exe` |

---

## PyInstaller 后端打包

### spec 文件

项目提供多架构的 PyInstaller spec 文件：

| 文件 | 目标架构 |
|------|---------|
| `backend/assistance-management-backend-x64.spec` | Windows x64 |
| `backend/assistance-management-backend-x86.spec` | Windows x86 |

### 打包命令

```bash
cd backend

# x64 架构
pyinstaller assistance-management-backend-x64.spec

# x86 架构
pyinstaller assistance-management-backend-x86.spec
```

### spec 关键配置

```python
# 无控制台窗口（生产环境）
console=False

# 隐藏导入
hiddenimports=[
    'uvicorn.logging',
    'uvicorn.loops.auto',
    'sqlalchemy.ext.asyncio',
    'passlib.handlers.bcrypt',
]

# 数据文件
datas=[
    ('alembic/', 'alembic/'),
    ('alembic.ini', '.'),
]
```

### 常见问题

1. **ProactorEventLoop 警告**：`start.py` 已修复，PyInstaller 打包后自动处理
2. **GBK 编码问题**：`start.py` 已设置 `sys.stdout` 为 UTF-8
3. **libmagic 崩溃**：`backend/app/core/file_upload.py` 已改用 `mimetypes` 代替 `python-magic`

## electron-builder 前端 + 壳打包

### 前端构建

```bash
cd frontend
npm run build
```

构建产物输出到 `resources/frontend/`。

### Electron 打包配置

`electron-builder` 配置在 `frontend/package.json` 的 `build` 字段中。

```bash
cd frontend

# 构建 Windows x64 安装程序
npm run build:win

# 构建 Windows x86 安装程序
npm run build:win32
```

### 构建产物

| 产物 | 路径 |
|------|------|
| NSIS 安装程序 | `frontend/dist/帮扶管理信息系统 Setup x.x.x.exe` |
| 免安装版 | `frontend/dist/win-unpacked/` |

## NSIS 钩子

NSIS 安装脚本钩子位于 `build-scripts/` 目录：

| 文件 | 说明 |
|------|------|
| `build-scripts/installer.nsh` | NSIS 自定义安装逻辑 |
| `build-scripts/postinstall.bat` | 安装后执行脚本（VC++ 运行库安装） |
| `build-scripts/preuninstall.bat` | 卸载前清理脚本 |

### NSIS 自定义功能

- **安装路径选择**：默认 `C:\Program Files\帮扶管理信息系统`
- **VC++ Redist 自动安装**：检测并安装 VC++ 2015-2022 运行库
- **桌面快捷方式**：自动创建
- **开始菜单**：程序组 + 卸载入口
- **静默安装**：`/S` 参数支持

## build.ps1 使用

`scripts/docker/build.ps1` 提供 Docker 一键构建脚本（2026-08-27 自根目录归位）：

```powershell
# 构建 x64 完整安装包
.\scripts\docker\build.ps1 -Arch x64

# 构建 x86 完整安装包
.\scripts\docker\build.ps1 -Arch x86

# 构建所有架构
.\scripts\docker\build.ps1 -Arch all

# 仅构建后端
.\scripts\docker\build.ps1 -Arch x64 -BackendOnly

# 仅构建前端+Electron
.\scripts\docker\build.ps1 -Arch x64 -FrontendOnly
```

### build.ps1 流程

1. 同步版本号（`scripts/sync_version.py`）
2. 清理旧的构建产物
3. 构建前端（`npm run build`）
4. PyInstaller 打包后端
5. electron-builder 打包安装程序
6. 输出最终产物路径

## CI/CD 构建工作流

`.github/workflows/build-windows.yml` 自动化构建工作流：

```yaml

  - windows-2019, x64
  - windows-2019, x86

  1. Checkout 代码
  2. 设置 Python 3.11
  3. 安装 Python 依赖
  4. 设置 Node.js 18
  5. 安装前端依赖
```

## 故障排查

| 问题 | 解决方案 |
|------|---------|
| PyInstaller 找不到模块 | 在 `.spec` 文件的 `hiddenimports` 中添加 |
| electron-builder 签名错误 | 开发环境跳过签名：`CSC_IDENTITY_AUTO_DISCOVERY=false` |
| 打包后体积过大 | 检查 `excludes` 排除不需要的模块 |
| VC++ 运行库缺失 | 安装程序自动处理；手动安装：`resources/vcredist/` |
| 杀毒软件误报 | 提交到 Microsoft Defender 白名单分析 |
