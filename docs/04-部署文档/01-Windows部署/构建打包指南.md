# Windows 构建打包指南

> 帮扶管理信息系统 — Windows 安装程序构建指南

本文档说明如何从源码构建 Windows `.exe` 安装程序。**现役只出 x64 单架构**（x86/32 位已放弃：
上游 numpy/scipy/scikit-learn 不再提供 win32 cp311 wheels）。

---

## 推荐路径：推标签，让 GitHub 一次产出两个安装包

本地无需完整构建链，推 `v*` 标签即可由 Actions 产出并发布 **Windows x64 安装包** 与
**麒麟 ARM64 deb 包**：

```bash
# 1) 本地先跑通门禁（后端 pytest + 覆盖率 100%、前端 vitest、flake8、bandit、6 个棘轮门禁）
cd backend && .venv/Scripts/python.exe -m pytest tests/ -q --cov=app
cd ../frontend && npm test -- --run

# 2) 提交并推标签（标签触发 build-windows.yml 与 build-arm64.yml，产物挂到 GitHub Release）
git tag v1.12.17 && git push origin v1.12.17
```

产物：Releases 页面的 `MRRS-Setup-1.12.17-x64.exe`（约 230 MB）与 ARM64 `.deb`，
以及完整性清单 `SHA256SUMS-windows-x64.txt` / `SHA256SUMS-*-deb-arm64.txt`。

> 本系统为**离线单机部署，无自动更新**（有意设计）——安装包只发 `.exe`/`.deb` 与
> `SHA256SUMS-*.txt`，不产出也不消费 `latest.yml`/`*.blockmap`。升级 = 下载新版安装包覆盖安装，
> 流程见《[离线升级与回滚指南](../OFFLINE_UPGRADE.md)》。

> ⚠️ 本机若无 `make`（Windows 默认不带），**直接跑已固化的一键脚本**（等价 `make build-win-x64`）：
>
> ```powershell
> powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build-installer-local.ps1
> ```
>
> 内部依次执行：`fetch_vcredist.ps1` → `npm run build`（frontend）→
> `scripts\build\sync-frontend-dist.bat`（把 `frontend/dist` 备份到 `resources/frontend`，
> 仅供完整性清单/静态资源审计使用）→ PyInstaller（`assistance-backend.spec`）
> → `npx electron-builder --win --x64`；任一步失败即中止并明确报错。
>
> 注意：**安装包里的前端来自 `frontend/dist`**（`package.json` `build.extraResources`
> 的 `from` 就是它），不是 `resources/frontend`。后者只是同名副本，改动它不影响出包。

## 构建概览

整体构建流程：

```
源码 → PyInstaller 打包后端 → electron-builder 打包前端+Electron壳 → NSIS 安装程序
```

| 组件 | 工具 | 产物 |
|------|------|------|
| 后端 (Python) | PyInstaller | `backend/dist/assistance-backend/`（onedir：主 exe + `_internal/`） |
| 前端 (Vue 3) | Vite build | `frontend/dist/`（electron-builder 复制为安装包内 `resources/frontend/`） |
| 桌面壳 (Electron) | electron-builder | NSIS 安装程序 `dist/electron/MRRS-Setup-<版本>-x64.exe` |

## PyInstaller 后端打包

### spec 文件

Windows x64 与麒麟 ARM64 共用一份 `backend/assistance-backend.spec`（onedir，见
ADR-0006）；ARM64 另有 `backend/backend_linux_arm64.spec`（Electron DEB 用后端）与
`backend/backend_linux_arm64_standalone.spec`（standalone DEB）。
**32 位（x86）已放弃**：上游 numpy/scipy/scikit-learn 不再提供 win32 cp311 wheels；
早期文档提到的 `assistance-management-backend-x64/x86.spec` 在仓库中已不存在。

### 打包命令

```bash
cd backend

# Windows x64（正规格口，CI 与本地一键脚本都用这一条）
python -m PyInstaller assistance-backend.spec --clean --noconfirm
```

### spec 关键配置

```python
# 无控制台窗口（生产环境；生命周期由 Electron 主进程管理）
console=False

# onedir：exe 仅含引导器，依赖与数据交给 COLLECT
exclude_binaries=True
name='assistance-backend'          # 产物目录 backend/dist/assistance-backend/

# 数据文件：运行时按路径扫描的文件必须保留；app 源码不进 datas（走 PYZ 字节码）
datas=[
    ('alembic/', 'alembic/'),
    ('alembic.ini', '.'),
    ('.env.example', '.'),
    # H12：app/core/_build_info.json 存在时条件收录（CI 打包前由
    # scripts/generate_build_info.py 生成；缺失则 /health/full 指纹回落 dev）
]

# app.* 全量收集（含动态注册的业务路由），避免手写 hiddenimports 遗漏
hiddenimports += collect_submodules('app')

# 打包卫生：剔除第三方库自带 tests/ 目录（sklearn 等会把夹具数据带进产物）
a.datas = _strip_test_data_toc(a.datas)
```

### 常见问题

1. **ProactorEventLoop 警告**：`start.py` 已修复，PyInstaller 打包后自动处理
2. **GBK 编码问题**：`start.py` 已设置 `sys.stdout` 为 UTF-8
3. **libmagic 崩溃**：`backend/app/core/file_upload.py` 已改用 `mimetypes` 代替 `python-magic`

## electron-builder 前端 + 壳打包

### 前端构建

```bash
cd frontend
npm run build
```

构建产物输出到 `frontend/dist/`；electron-builder 打包时按
`package.json` 的 `build.extraResources`（`from: frontend/dist` → `to: frontend`）
复制为安装包内的 `resources/frontend/`。`electron/main.js` 打包态只读
`process.resourcesPath/frontend`，并把它作为 `FRONTEND_DIST_PATH` 注入后端进程。

### Electron 打包配置

`electron-builder` 配置在**根目录** `package.json` 的 `build` 字段中
（`frontend/package.json` 只有前端自身的 scripts；前端构建脚本**不要**在那里找打包配置）。

```bash
# 在仓库根目录执行
npm run check:electron     # node --check electron/*.js（打包前语法门禁）
npm run build:win          # check:electron + build:backend + electron-builder --win --x64
npm run build:deb          # electron-builder --linux deb
npm run build:arm64        # electron-builder --linux deb --arm64（麒麟）
npm run pack               # electron-builder --dir（免安装目录，调试用）
```

### 构建产物

| 产物 | 路径 |
|------|------|
| NSIS 安装程序 | `dist/electron/MRRS-Setup-<版本>-x64.exe`（`build.artifactName`） |
| 免安装版 | `dist/electron/win-unpacked/` |
| ARM64 DEB | `dist/electron/MRRS-Setup-<版本>-arm64.deb` |

## NSIS 钩子

NSIS 安装脚本钩子位于 `build-scripts/` 目录：

| 文件 | 说明 |
|------|------|
| `build-scripts/electron-builder-nsis-hook.nsh` | NSIS 自定义安装钩子（现役，package.json `nsis.include` 引用） |

> 注: 旧版 `installer.nsh` / `postinstall.bat` / `preuninstall.bat` 已废弃删除，
> VC++ 运行库安装与卸载清理统一由 electron-builder-nsis-hook.nsh 处理。

### NSIS 自定义功能

- **安装路径选择**：默认 `C:\Program Files\帮扶管理系统`（`package.json` `nsis.perMachine=true`
  + `allowToChangeInstallationDirectory=true`）
- **VC++ Redist 自动安装**：检测并安装 VC++ 2015-2022 运行库（源码来自
  `build.win.extraResources` 的 `resources/vcredist`，仅 Windows 产物携带）
- **桌面快捷方式**：自动创建（`nsis.createDesktopShortcut=always`）
- **开始菜单**：程序组 + 卸载入口
- **静默安装**：`/S` 参数支持
- **卸载数据清理**（H11，2026-10-14）：安装期把真实 userData（`%APPDATA%\帮扶管理系统`）
  写入注册表，卸载时读回后按用户选择删除；同时清理旧版遗留的
  `%LOCALAPPDATA%\bumofu-assistance`

## build.ps1 使用

`scripts/docker/build.ps1` 提供 Docker 一键构建脚本（2026-08-27 自根目录归位）：

```powershell
# 构建 x64 完整安装包
.\scripts\docker\build.ps1 -Arch x64

# 构建 x86 完整安装包
.\scripts\docker\build.ps1 -Arch x86

# 构建所有架构
.\scripts\docker\build.ps1 -Arch all

# 仅构建后端
.\scripts\docker\build.ps1 -Arch x64 -BackendOnly

# 仅构建前端+Electron
.\scripts\docker\build.ps1 -Arch x64 -FrontendOnly
```

### build.ps1 流程

1. 同步版本号（`scripts/sync_version.py`）
2. 清理旧的构建产物
3. 构建前端（`npm run build`）
4. PyInstaller 打包后端
5. electron-builder 打包安装程序
6. 输出最终产物路径

## 故障排查

| 问题 | 解决方案 |
|------|---------|
| PyInstaller 找不到模块 | 在 `.spec` 文件的 `hiddenimports` 中添加 |
| electron-builder 签名错误 | 开发环境跳过签名：`CSC_IDENTITY_AUTO_DISCOVERY=false` |
| 打包后体积过大 | 检查 `excludes` 排除不需要的模块 |
| VC++ 运行库缺失 | 安装程序自动处理：内置安装器先做 SHA256 校验——匹配则静默安装；不匹配（真实损坏/篡改）弹窗中止；校验工具不可用（如被安全软件阻断 PowerShell）则跳过 redist 安装但不阻断部署（应用内置运行时 DLL 兜底）。构建机缺 `resources/vcredist/` 时先跑 `make fetch-vcredist`（官方 URL 下载 + SHA256 钉扎校验，二进制不入库） |
| 杀毒软件误报 | 提交到 Microsoft Defender 白名单分析 |
