# Windows 代码签名接入指南（W6-T1）

> 状态：**管线已就绪，等待证书采购**。本文档描述签名管线的接入方式、
> 需要配置的密钥与验证方法。证书（建议 EV/OV + 硬件令牌）采购到位后，
> 按第二节配置 secrets 即自动启用，无需改代码。

## 一、管线行为（已实现）

| 构建对象 | 签名方式 | 生效条件 |
|----------|----------|----------|
| `assistance-backend.exe`（PyInstaller onedir 主程序） | CI 第 8.5 步 `signtool sign /fd SHA256 /tr <RFC3161 时间戳>` | secrets 配置了 `CSC_LINK` |
| NSIS 安装包 + 卸载器 | electron-builder 在打包阶段自动签名（读取同一对 CSC 密钥） | 同上 |

未配置 `CSC_LINK` 时：构建**不会失败**，第 8.5 步输出显式 WARNING
（"跳过代码签名，军队白名单场景需要签名"）后继续。

## 二、接入步骤（证书到位后）

1. 将证书导出为 PFX（含私钥）；若签发机构提供硬件令牌（EV 常见），
   改用支持令牌的签名方式并联系平台管理员调整第 8.5 步参数。
2. GitHub 仓库 **Settings → Secrets and variables → Actions** 配置：
   - `CSC_LINK`：PFX 文件的 **base64 编码**（`base64 -w0 cert.pfx`），
     或一个构建机可访问的文件路径；
   - `CSC_KEY_PASSWORD`：PFX 私钥密码。
3. 手动触发一次 `Build Windows Installer (x64)`（workflow_dispatch，
   不建 Release），在日志中确认：
   - 第 8.5 步无 WARNING，输出"后端 exe 已签名并通过验证"；
   - 第 10 步 electron-builder 无 `skipped code signing` 类提示；
4. 验证通过后打 tag 走正式发版。

## 三、签名验证方法（发版后 / 审计）

PowerShell（目标机即可执行）：

```powershell
# 查看签名状态与证书链
Get-AuthenticodeSignature ".\帮扶管理系统 Setup 1.11.4.exe" | Format-List
# Status 必须为 Valid；StatusMessage 为空或 TheDigitalSignatureIsOk

# 命令行深度校验（含证书链与吊销状态）
signtool verify /pa /all ".\帮扶管理系统 Setup 1.11.4.exe"
```

签名时间戳（RFC3161）保证证书到期后既有签名仍然可信；时间戳服务
`timestamp.digicert.com` 仅在**签名时**（CI 构建机）访问，目标机无需联网。

## 四、与完整性链的关系

- SHA256SUMS（W6-T5）校验的是**文件内容完整性**（传输损坏/替换检测）；
- 代码签名校验的是**发布者身份与签发后未被篡改**；
- 军队分发场景两者都要：先 `sha256sum -c`，再验签（见
  [离线升级与回滚指南](../OFFLINE_UPGRADE.md) 第二节）。

## 五、CI 自动签名（v1.18.3 起有门禁）

`build-windows.yml` 在 electron-builder 之前按需写入签名环境变量（**仅当 secret 存在时**）：

| Secret | 作用 |
|---|---|
| `CSC_LINK` | 证书（base64 的 .pfx 或 URL）；**未配置则不签名**，不会把空串当证书路径 |
| `CSC_KEY_PASSWORD` | 证书口令 |

构建后新增 **`Verify installer signature` 步骤**：

- `CSC_LINK` 非空 → `Get-AuthenticodeSignature.Status` 必须为 `Valid`，否则**构建失败**
  （防止"以为签了其实没签"）；
- `CSC_LINK` 为空 → 明确 `::warning::` + 写入 Step Summary「本构建未做代码签名，请以 SHA256SUMS 校验完整性」，
  构建不失败（当前无证书阶段的正常状态）。

> 现状（2026-10-25）：证书尚未采购，CI 走"未签名 + SHA256SUMS"路径；采购后只需在仓库
> Settings → Secrets 添加上述两项即可自动启用签名，无需改代码。

## 四、构建后全产物校验（脚本，证书到位前后都能跑）

`Verify installer signature` 只校验 `dist/electron/*.exe`（安装器）。后端主程序在
`dist/electron/win-unpacked/resources/backend/**` 下，安装器签名不会覆盖它，因此
2026-11-01（短期项 8）补了**全产物**校验脚本：

```powershell
# 只报告（无证书阶段的日常用法）：未签名只 WARN，仍 PASS
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_installer_signature.ps1 -Path dist/electron

# 发版硬门禁（证书到位后）：任何未签名/签名无效都 exit 1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_installer_signature.ps1 -Path dist/electron -RequireSignature
```

判定口径：

| 状态 | 默认 | `-RequireSignature` |
|------|------|---------------------|
| `Valid`（含签名主体打印） | 通过 | 通过 |
| `NotSigned` | WARN，整体 PASS | **FAIL** |
| `UnknownError` / `HashMismatch` / `NotTrusted` 等 | **FAIL**（伪造/篡改/证书链不受信） | **FAIL** |

CI 的 `build-windows.yml` 已接入 `Verify all exe signatures` 步骤：有 `CSC_LINK`
时自动带 `-RequireSignature`，无证书时只告警，口径与 `Verify installer signature` 一致。

> 注意：脚本含中文输出，文件必须保存为 **UTF-8 with BOM**（Windows PowerShell 5.1
> 按 ANSI 读取无 BOM 的 UTF-8 会解析失败）。改脚本后请用
> `[System.IO.File]::ReadAllBytes` 确认前三字节为 `EF BB BF`。
