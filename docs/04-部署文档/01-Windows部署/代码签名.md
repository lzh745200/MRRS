# Windows 代码签名接入指南（W6-T1）

> 状态：**管线已就绪，等待证书采购**。本文档描述签名管线的接入方式、
> 需要配置的密钥与验证方法。证书（建议 EV/OV + 硬件令牌）采购到位后，
> 按第二节配置 secrets 即自动启用，无需改代码。

## 一、管线行为（已实现）

| 构建对象 | 签名方式 | 生效条件 |
|----------|----------|----------|
| `assistance-backend.exe`（PyInstaller onedir 主程序） | CI 第 8.5 步 `signtool sign /fd SHA256 /tr <RFC3161 时间戳>` | secrets 配置了 `CSC_LINK` |
| NSIS 安装包 + 卸载器 | electron-builder 在打包阶段自动签名（读取同一对 CSC 密钥） | 同上 |

未配置 `CSC_LINK` 时：构建**不会失败**，第 8.5 步输出显式 WARNING
（"跳过代码签名，军队白名单场景需要签名"）后继续。

## 二、接入步骤（证书到位后）

1. 将证书导出为 PFX（含私钥）；若签发机构提供硬件令牌（EV 常见），
   改用支持令牌的签名方式并联系平台管理员调整第 8.5 步参数。
2. GitHub 仓库 **Settings → Secrets and variables → Actions** 配置：
   - `CSC_LINK`：PFX 文件的 **base64 编码**（`base64 -w0 cert.pfx`），
     或一个构建机可访问的文件路径；
   - `CSC_KEY_PASSWORD`：PFX 私钥密码。
3. 手动触发一次 `Build Windows Installer (x64)`（workflow_dispatch，
   不建 Release），在日志中确认：
   - 第 8.5 步无 WARNING，输出"后端 exe 已签名并通过验证"；
   - 第 10 步 electron-builder 无 `skipped code signing` 类提示；
4. 验证通过后打 tag 走正式发版。

## 三、签名验证方法（发版后 / 审计）

PowerShell（目标机即可执行）：

```powershell
# 查看签名状态与证书链
Get-AuthenticodeSignature ".\帮扶管理系统 Setup 1.10.6.exe" | Format-List
# Status 必须为 Valid；StatusMessage 为空或 TheDigitalSignatureIsOk

# 命令行深度校验（含证书链与吊销状态）
signtool verify /pa /all ".\帮扶管理系统 Setup 1.10.6.exe"
```

签名时间戳（RFC3161）保证证书到期后既有签名仍然可信；时间戳服务
`timestamp.digicert.com` 仅在**签名时**（CI 构建机）访问，目标机无需联网。

## 四、与完整性链的关系

- SHA256SUMS（W6-T5）校验的是**文件内容完整性**（传输损坏/替换检测）；
- 代码签名校验的是**发布者身份与签发后未被篡改**；
- 军队分发场景两者都要：先 `sha256sum -c`，再验签（见
  [离线升级与回滚指南](../OFFLINE_UPGRADE.md) 第二节）。
