# v1.18.35 发布说明 — 组织策略树、表格填报导入修复与历史数据恢复

发布日期：2026-11-02

## 谁需要升级

- **所有使用表格填报导入的单位**：旧版在模板示例行上直接填写时，整行会被静默丢弃——
  界面提示成功、实际入库 0 条。本版修复该缺陷，并对「一行都没解析到」明确返回 400 与操作提示。
- **需要从历史备份恢复的工位**：旧备份的文件定位、manifest 版本校验与低版本 SQLite DDL
  兼容性已修复，历史备份可被正确识别与恢复。
- **有省 / 市 / 县三级组织的单位**：授权改为「组织策略树 + 四态矩阵 + 每单位一个 v1 包」，
  支持按子树批量导出填报包。
- **数据交换 / 运维岗**：审计、备份恢复、数据同步与前端若干并发问题一并修复。

## 本版改动

### 1. 表格填报导入修复（R61）

- 根因：旧 `_is_skippable_row` 只要行内任意单元格含「示例行」就整行跳过；用户直接在示例行
  上改成真实数据（模板末尾第 20 列的「示例行」注释仍在）时，整行被静默丢弃。
- 新规则：仅当「首列仍是示例值」且「行内带示例行注释」时跳过；仅首列示例标记、
  或仅页脚说明行（`填写说明 / 填报说明 / 帮扶管理信息系统 v`）才跳过；保留注释的真实数据正常导入。
- 解析成功但 0 行时返回 **400**，提示在示例行下方新增数据行或替换首列示例值；
  文件损坏 / 格式不支持仍按原契约返回 200 + errors（避免把解析失败误判为 0 行）。
- 新增 **一户一档** 导入模板与导入逻辑（按村名 + 县 + 乡镇解析帮扶村；户编号村内唯一）。

### 2. 单条 / 批量导出填报表格并回导（R61）

- 新增 `GET /api/v1/import/export-fill?entity_type=&ids=`：按官方模板表头导出数据，
  末尾追加 `ID` 列；支持帮扶村 / 项目 / 资金 / 学校 / 一户一档。
- 数据范围仍走 `scoped_filter` 数据权限与 `is_active` 过滤，单次上限 5,000 行。
- 回导：带 `ID` 的行按 ID 更新（越权或不存在记失败，不新建）；无 `ID` 的行保持增量去重新增。
- 前端「数据导入」页新增「导出填报表格（修改后可回导）」卡片：可选类型与记录 ID（空 = 全部），
  批量导出与单条导出共用同一接口。

### 3. 历史备份与恢复兼容（R57）

- 备份 manifest 升级为 `format_version=2`，写入 `app_version` 与 `schema_revision`；
  历史备份缺少这些字段时按可升级处理，不再误拒。
- 新增备份库多路径回退定位（标准路径 → `data/assistance.db` → `data/assistance_management.db`
  → 根目录同名 → `data` 下唯一 `.db`），旧备份文件可被识别后恢复。
- 新增 SQLite 版本兼容 DDL 助手：`DROP COLUMN`（<3.35）与 `RENAME COLUMN`（<3.25）
  自动回退到 `batch_alter_table` 重建表，旧环境执行迁移不再失败。

### 4. 组织策略树（R48）

- 新增 `GET /api/v1/org-grants/tree`：按组织树返回显式授权；超管未绑定单位时默认取组织树顶层。
- 新增 `POST /api/v1/org-grants/{id}/export-branch`：按子树计算每单位有效矩阵并打包 zip
  （`grant-{code}-v{version}.json` + `manifest.json`），空矩阵单位跳过并在 manifest 告警；
  缺单位编码整体 400 且不消耗版本。
- 前端授权页改为「组织树 + 四态矩阵（继承 / 可操作 / 只读 / 不开放）+ 继承来源 + 导出本子树」；
  显式 `none` 会提交（与「缺失=继承」区分）。
- 组织级 `data_scope` 仅做影子观测（`ORG_DATA_SCOPE_MODE`，默认 `off`，不改变查询结果）；
  写闸门与组织模块策略收敛到 `core/module_edit_rules.py` 单一来源，更严者生效。

### 5. 其他并发修复

- 审计日志时间边界（`to_utc_naive` + 结束日期包含当天）、备份信息解析与恢复线程校验、
  数据同步「失败记录为 0 才成功」判定、r39/r40/r43 迁移在旧库上的兼容。
- 前端：审批中心、待办、项目/学校保存、附件 CSRF、分块上传轮询、数据包版本对比、未读数。
- 构建脚本默认版本统一到 1.18.35。

## 升级步骤

1. 先备份：系统管理 → 备份与存储 → 创建备份（确认文件已加密且下载 / 留存）。
2. 关闭应用（任务栏退出，确认进程结束）。
3. 运行新安装包覆盖安装（默认路径不变则数据 / 密钥沿用 `%LOCALAPPDATA%\bumofu-assistance\data`）。
4. 启动后点检：
   - 数据管理 → 数据导入：下载模板，在示例行下方新增一条数据后导入；
   - 数据导入页「导出填报表格」导出全部，修改一行后回导，确认是更新而不是新增；
   - 系统管理 → 组织权限：打开组织树，确认四态矩阵与「导出本子树」可用；
   - 备份与存储：用一份历史备份做一次恢复演练（先在测试库验证）。

## 已知限制

- 安装包仍**未做代码签名**（无证书），Windows SmartScreen 首次运行会提示。
- 组织级 `data_scope` 默认 `off`（仅影子观测）；`ORG_MODULE_POLICY_MODE` 默认 `shadow`，
  确认无副作用后再切 `enforce`。
- 授权包 `valid_until` 目前只提示不降级；过期仍需人工重新签发。
- 空数据表（0 行）从「静默成功」改为 400 是**有意的行为变更**，依赖旧行为的脚本需调整。
- 本地 Windows 构建机的 NSIS 卸载器生成在非管理员 / 非交互会话会挂起，发布构建由 CI 完成。
