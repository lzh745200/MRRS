## 二、⚠️ 升级前必读

### 1. 数据库迁移（必读）

本版包含 **r36 ~ r41 六个迁移**（清理零引用表与列）。升级路径经过演练验证：
**v1.16.4（r35）→ v1.17.1（r41）可完整接管，124 张表数据完好**。

- 安装包首启自动迁移到 head（**61 个 Alembic 版本，单 head**）
- **升级前请先备份**（系统管理 → 备份与存储 → 备份），或离线复制
  `%APPDATA%\Assistance-Management-Information-System\data\rural_revitalization.db`
- 迁移遵循「空表 DROP / 有数据改名 `legacy_<表名>` 归档」契约，**不会删有数据的表**
- 迁移失败时启动自检直接 `SystemExit(1)` 保留现场，不会静默重建库

### 2. PII 密钥必须与上级一致（多机部署）

多机同步场景下 `ENCRYPTION_KEY` 必须全实例一致，否则对方的 PII 密文在本机解不开。
本版起可在 **系统管理 → 系统设置 → 系统自检** 直接查看本机 **PII 密钥指纹**，与上级比对即可。

### 3. 介质导入的新增拦截行为（重要变更）

本版起数据包/授权包/权限包/配置包导入会做**整包查重**与**来源单位码核对**：

- **同一个包重复导入** → 返回 409「该数据包已于 X 由 Y 导入过」，需在弹窗里选「仍然导入」才放行
- **包内单位码与本机不一致** → 返回 409「数据包来源单位码为 A，与本机单位码 B 不一致」，需显式放行
- 两类拦截都会写入审计台账（`package_import` / `package_receipt`），可追溯

> 升级后首次导入历史数据包时若被拦，属预期行为：先确认包来源，再决定是否放行。

### 4. 自助注册默认关闭

`SELF_REGISTER_MODE=off`（出厂默认）：自助注册入口返回
「系统已关闭自助注册，请联系管理员创建账号」。需要临时开放时改为 `controlled`。

## 三、本版主要变更

### v1.17.1 —— 版本口径与构建修复

- **`/health` 版本号不再被陈旧构建指纹覆盖**：`_build_info.json` 是 CI 构建产物（已 gitignore），
  开发机残留旧指纹时 `/health` 曾报旧版本（实测 1.15.7 vs 代码 1.17.0）。现明确
  **版本唯一权威 = `settings.PROJECT_VERSION`**（由根 `package.json` 单源同步）。
- **`build-installer-local.ps1` 补 UTF-8 BOM**：此前 Windows PowerShell 5.1 按 GBK 解析中文脚本
  导致语法错误，**本地安装包构建完全不可用**；修复后本地构建成功。
- 新增用户手册《介质数据包导入与系统自检操作说明》。

### v1.17.0 —— 介质链路治理 + 系统自检 + W27 全栈收敛

**介质链路治理（P2）**

- 整包查重（SHA256 指纹 → `audit_logs` 台账），重复默认 409，可显式放行
- 导入台账 `package_import` + 导入回执 `package_receipt`（**复用审计表，零新增迁移**）
- 来源单位码核对（`package_org_code`），不一致默认阻断
- 冲突策略落库（逐条比对 / 以包为准），事后可追溯
- 前端统一确认弹窗 `ImportPreviewDialog`

**系统自检（P3）**

- `GET /api/v1/system/self-check`（仅管理员）+ 设置页卡片，一次体检 6 项：
  单位码（缺失/格式/层级不符/重复）、组织层级（跨级挂接/根非省级）、待审核账号、
  账号锁定、PII 密钥指纹、介质导入近况（近 30 天失败数）

**W27 全栈收敛**

- 包完整性校验：管控包/配置包/权限包导入强制 checksum；配 `PACKAGE_PUBKEY` 后强制验签
- 经费禁止自批（`FUND_ALLOW_SELF_APPROVAL` 默认 False）
- 跨机业务键修复（`BUSINESS_KEYS` 改为「组织 + 业务唯一标识」）——
  修复同组织两台机器导入时"记录被整体覆写或静默丢弃"的 P0 缺陷
- 迁移 r36~r41 清理零引用表；新增两道门禁（测试必须有断言、同步链路覆盖）

## 五、升级步骤（Windows）

1. **备份数据库**（系统管理 → 备份与存储 → 备份）
2. 关闭正在运行的旧版本
3. 运行 `MRRS-Setup-1.17.1-x64.exe`，按向导覆盖安装（保留原数据目录）
4. 首次启动自动迁移到 head（约 10~30 秒，请勿中断）
5. 登录后进入 **系统管理 → 系统设置**，点「系统自检」确认 6 项均为正常/提醒
6. 抽查一条业务数据可正常打开、导出
