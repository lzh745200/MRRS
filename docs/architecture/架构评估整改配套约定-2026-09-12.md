## E2 · /shutdown 端点信任边界标注

**现状**：`/api/v1/shutdown` 仅接受 `127.0.0.1` + `X-Internal-Shutdown` 密钥
（Electron 每次启动用 `crypto.randomBytes(16)` 生成并注入环境变量）。

**信任边界（本文档即为正式标注）**：

- 密钥经**进程环境变量**传递。Windows 下同机低权限进程理论上可枚举
  其他进程的环境块（PEB），从而获取 shutdown 密钥。
- 因此本端点的威胁模型是"防误触/防远程"，**不防本机已运行的高权限进程**
  ——本机管理员本来就能直接杀进程，防线不因此退化。
- 单机离线部署下风险评级：**低（可接受）**。
- 若未来威胁模型升级（多用户共用主机），替代方案：命名管道/本地 socket
  或 Electron 直连信号量，见评估报告 E2。

## F2 · 覆盖率豁免清单约定

100% 分支覆盖门禁保留，但"为覆盖而写"须受控：

1. **豁免手段唯一**：`# pragma: no cover`，且**必须同行注明理由**：
   `except Exception as e:  # pragma: no cover — 仅防御性兜底，测试无法注入`
   无理由的裸 pragma 视同违规（评审拒绝合入）。
2. **显式豁免清单**（现存主要条目，新增须在此登记）：

   | 位置 | 理由 |
   |---|---|
   | `main.py` sys.stdout/stderr 为 None 分支 | PyInstaller windowed EXE 专有，pytest 环境不可达 |
   | `main.py` alembic head 推断失败兜底 | 仅 alembic 版本异常时触发的防御分支 |
   | `startup/monitors.py` 数据库自检线程异常兜底 | 线程内注入异常的测试成本高于收益 |
   | `backup_scheduler.py` subscription_dispatch_job | 并行会话在途（工单003），功能收口后补测 |

3. **优先级**：行为断言测试 > 覆盖凑数测试；同一分支已有行为断言覆盖时
   不再为个别行补"假测试"。

## B2 · services/ 分包规划（分批第一步：规划）

`app/services/` 80+ 文件平铺，按评估建议**分批迁移**，本期仅落地规划与
约定（不改任何 import 路径，零行为变更）：

| 批次 | 目标子包 | 迁移范围（示例） |
|---|---|---|
| 1（下个迭代） | `services/system/` | backup_service、backup_scheduler、system_config_service、update_log_service、db_maintenance |
| 2 | `services/reports/` | report_service、analytics_service、export 相关、restore_drill_service |
| 3 | `services/security/` | lockout_service、token_blacklist、audit_event_handler、runtime_secrets |
| 4 | `services/business/` | village/fund/project/school 域服务 |

**迁移规则**（每批必须遵守）：

- 旧路径 `app/services/xxx.py` 保留为**重导出 shim**（`from app.services.system.xxx import *`），
  至少保留两个版本周期；
- `services/__init__.py` 不做隐式聚合导入（避免循环导入）；
- 每批迁移独立提交，全量回归后合入；
- `collect_submodules('app')` 已覆盖子包，无需改打包配置。

## C1 · RPO / RTO 与备份策略基线

| 项 | 目标值 | 保障机制 |
|---|---|---|
| RPO（可容忍数据丢失窗口） | ≤ 24h | 每日 02:00 自动备份（`backup_interval_days` 可缩短） |
| RTO（恢复时间目标） | ≤ 1h | 备份包 + `restore_backup` 端点/Electron 恢复流程 |
| 备份可用性验证 | 每月（`restore_drill_interval_days`，默认 30） | `restore_drill_job`：还原到临时库 + integrity_check + 核心表抽查 |
| 备份保留 | 7 天（`backup_retention_days`） | 自动清理 + 管理员提醒 |
| 备份存放 | 默认应用数据目录；**强烈建议**配置 `backup_target_dir` 指向**独立物理盘/U盘**（`auto_package_dir` 同理）——与数据库同盘时断电/盘损场景备份与数据同亡 |

演练结论暴露在无认证端点 `/health` 的 `restore_drill` 字段
（status / checked_at / backup_file / error_type），供运维巡检。
