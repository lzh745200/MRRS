## 3. 已修复项详解（提交 `06a9e994` / `7fb5e910`）

### 3.1 权限包导入提权（阻断）

**根因**：`/import` 与 `/confirm` 的鉴权是「非 admin **且** 非 loopback → 403」，等于把回环地址
当成免认证通道；而包里 `role` / `data_scope` 原样落库。任何登录用户在本机都能构造一个包，
把自己写成 `super_admin`，再重新登录。

**修法**（`api/v1/permission_package.py` + `services/permission_package_service.py`）：

- 已登录：非管理员一律 403；管理员可预览，但**只有超管**能把 `allow_privileged=True` 传给 confirm。
- 匿名：仅允许「回环 + 库内无任何账号」的首装场景，其余 403。
- 服务层 `_sanitize_legacy_privilege()`：非特权导入把 `super_admin→admin`、`data_scope=all→org`，
  未知角色归一为 `user`，并记 `stats["privileged_values_downgraded"]` 与告警日志。
- 测试：`test_permission_package_sec1.py`（14 例）+ 既有权限包测试同步，12 文件 **200 passed**。

### 3.2 超管端点错配（高）

新增 `core/permission_utils.require_superuser`（与 `require_admin` 同构：装饰器/直接调用两种形态，
缺失用户 401，非超管 403，fail-closed），替换 15 处：备份创建/删除/下载/预览/校验/恢复/上传恢复、
PII 主密钥导出/导入、关机/重启、`PUT /system/config`、配置包导入。低影响读接口保留 `require_admin`
并**只纠正文案**，避免过度收紧打断运维。

改为超管的 4 个既有 fixture 同步升级为 `super_admin`（策略变更，不是让步）；
`test_superuser_only_sec2.py`（22 例）+ 备份/PII/配置包全批 **181 passed**。

### 3.3 组织通行码越权（高）

`_scoped_org_ids()` 统一产出可见组织集合（超管 → 不限制；部门级 admin → 本组织及子树；
无组织 → 空集 fail-closed），校验码、通行码生成、列表、导出、删除全部经
`assert_org_reachable`；`get_organization_pass_codes(organization_ids=...)` 在 service 层再过滤一次
（防"忘了传参 = 查全表"）。测试：`test_machine_code_org_scope_sec3.py`（8 例）。

### 3.4 审计日志与校验码（中/低）

- 审计删除/改写改 `require_superuser`；留痕语义保留，但不再能被普通 admin 反复删除。
- `verify-machine-code` 加 20 次/60s 限流（按 TCP 对端 IP），让 4 位穷举从"秒级"变成"小时级"。
  没有改成 loopback-only，是因为注册页在局域网部署下也需要该校验。

### 3.5 媒体链路（中）

`resolve_upload_file` 增加 `is_relative_to(upload_root)` 断言；`load_image` 增加 5000 万像素上限
（Pillow 默认 1.78 亿才报警，解码 1 亿像素约 300MB）；对比图单元格宽上限 1440 并垂直居中。
新增 `test_media_hardening_1031.py`（6 例）。

### 3.6 前端四项（高/中/中/中）

- **锁屏绕过**：锁标记双写 `localStorage` + `sessionStorage`，路由守卫任一命中即拦截；
  `AuthStorage.clear()` 同时清锁（登出必须解锁）。
- **登出不吊销**：`logout()` 改为先发吊销请求、同步清理本地、返回 `Promise<void>`；
  布局层 `await logout()` 之后才 `freezeRequests()` 并跳转。
- **导入错误明细 XSS**：两处 `ElMessageBox` 对行号与错误文本逐项 `escapeHtml`（保留 `<br/>` 结构）。
- **草稿 PII**：`clearAllDrafts()` 在登出时删除所有 `form:draft:*`，不影响 `ui:prefs` / `nav:recent`。
- 测试：4 个相关文件 **90 passed** + 草稿 31 passed；`vue-tsc --noEmit` exit 0。

### 3.7 打包启动崩溃（阻断，已由 `7fb5e910` 修复并经本会话独立验证）

- 根因：standalone spec 的 `excludes` 含 `difflib`，而 `data_cleaning_service.py` 顶层 import 它。
- 修复：spec 不再排除标准库、`difflib` 进 `hiddenimports`；`assistance-backend.spec` 显式列出；
  新增 `scripts/verify_frozen_modules.py`（读 PyInstaller CArchive/PYZ 模块表）并接入四条打包链路；
  `start.py` 增 `BACKEND_IMPORT_CHECK` 自检入口。
- 验证（本会话实跑）：PYZ 4598 模块、384 项校验通过、`app.*` 379 个全收录；打包后端冷启动
  **18s 内** `/health/liveness` 200、`/health` healthy、`/version.json` 1.18.31。

  "换 id 挂错"类问题。

- **依赖与安全基线自动化**：`pip-audit` + `npm audit` 进 CI（当前依赖已全量钉版本，成本低）。

### 明确不做（取舍）

- 不引入 PostgreSQL/Redis：单机离线是本产品的核心约束，SQLite + 进程内缓存已满足；
  换栈会带来部署复杂度与离线包体积，收益不足以抵消风险。
- 不做微服务拆分：当前 845 端点单进程完全可承载县级数据量，拆分只会增加运维成本。
- 不为历史遗留表做数据迁移工具：`legacy_*` 归档策略已保证升级不中断，投入产出比低。

## 7. 假设与待确认

1. **权限包匿名导入仅限空库首装**：已有数据的机器需超管登录后导入。若现场流程是"先同步数据、
   未登录就导入权限包"，会收到 403——这是堵提权的必要收紧，需业务确认。
2. **管理员不再能确认导入权限包**（需超管）：因为 mirror 导入可写 `role/data_scope`，
   等价全库 RBAC 重写。若坚持"部门 admin 可导入"，替代方案是导入时强制降级超管值（已实现一半）。
3. **审计日志删除收紧为超管**：若运维需要部门级 admin 定期清理，应改为"保留期自动清理任务"
   而不是放开删除权限。
4. **"派单/通知平台说明"具体指向未明**：仓库内没有名为"派单"的模块，站内消息中心已在使用指南中；
   若指外部 OA/钉钉类平台，需要提供平台与凭据，本轮按"发布通知模板"形式给出（见交付说明）。
5. **Electron 升级**：会改变 Chromium 版本与部分 UI 行为，需单独排期与全量回归，不建议与本次
   修复混发。
6. **跨平台离线包**：本机无 Docker，Linux/ARM64 包无法本地复现构建，以 GitHub Actions 产物为准
   （v1.18.31、v1.18.32 两条 ARM64 工作流均 success；v1.18.32 三个资产已上传 Release）。
7. **安装器交互式安装未在本机自动化验证**：静默安装 `/S` 需 UAC 提权，本会话无交互能力
   （approval policy=never，无桌面），因此以「解包 payload 冷启动冒烟 + 冻结自检 + 资产 digest」为证据；
   Windows 真机一键安装（UAC 弹窗 → 首次启动）仍需人工确认一次。
