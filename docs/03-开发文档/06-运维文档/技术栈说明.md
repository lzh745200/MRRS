## 二、运行时依赖清单（单一事实源）

依赖登记表在 **`backend/app/core/required_packages.py`**，分三级：

| 级别 | 含义 | 内容（分发名） | 登记文件 |
|---|---|---|---|
| **运行时必需** | 缺任何一个系统不可用，启动自检即告警 | fastapi、uvicorn、sqlalchemy、pydantic、pandas、openpyxl | `backend/requirements.txt` |
| **运行时可选** | 缺失只影响对应功能（导出/图片），系统照常启动 | reportlab（PDF）、python-docx（Word）、pillow（图片） | `backend/requirements.txt` |
| **仅开发期** | 生产与安装包内本就没有，**不得**计入运行时缺失 | pytest、flake8、bandit | `backend/requirements-dev.txt` |

> ⚠️ **历史缺陷（2026-09-14 修复，R15）**：清单曾在 `app/main.py`、`app/startup/environment.py`、
> `app/api/v1/system/env.py` **三处各写一份**且互相漂移。UI 那份还列了应用**从不 import** 的
> `fpdf2`（`requirements.txt` 里也没有该分发名）与**仅开发期**的 `pytest` —— 结果：
> ① 任何环境下都恒报"缺失依赖"，用户照提示 `pip install fpdf2 pytest` 永远装不出 `fpdf2`（幻影依赖）；
> ② 校验用 `importlib.metadata.distributions()` 枚举已安装分发，而 PyInstaller 冻结运行时里
> bundled 包的 `.dist-info` 不完整 —— 明明能 import 的包也被判缺失，**安装包首启即误报"缺失 7 个依赖"**。

**新增/调整依赖的流程**：只改 `required_packages.py` 登记表 + 对应 `requirements*.txt`，
两处分发名必须一致（防止再出现"代码要求但清单里没有"的幻影依赖）。

## 三、依赖自检与诊断

| 入口 | 时机 | 行为 |
|---|---|---|
| 启动自检 `startup/environment.py::_check_required_packages` | 每次启动 | 逐条按 **import 名** 校验运行时必需依赖；缺失时打印业务名 + 修复命令（开发态）或"自包含运行时异常"（冻结态） |
| 环境诊断页 `GET /api/v1/env/check` | 系统管理 → 运行环境诊断 | 返回 `missing_packages`（红色故障）/ `optional_missing`（功能降级）/ `dev_missing`（仅开发期）/ `runtime_ok` / `fix_command` / 逐条明细 |

**校验口径**：是否安装用 `importlib.util.find_spec(import 名)`（冻结运行时同样可靠）；
版本号用 `importlib.metadata.version(分发名)` **尽力而为**，取不到不影响"已安装"判定。

**两种运行形态的差异**：

| 形态 | 依赖来源 | 缺依赖怎么办 |
|---|---|---|
| 源码/开发（`python start.py`） | `backend/.venv`（`pip install -r requirements.txt -r requirements-dev.txt`） | 按 `fix_command` 执行：`"<venv python>" -m pip install -r "<backend/requirements.txt>"` |
| 安装包（PyInstaller 冻结 + Electron 外壳） | 安装包内自包含（onedir `resources/backend/assistance-backend/`） | **无需也无法 pip 安装**；页面会提示"自包含安装包运行，请重新安装安装包或联系管理员" |
