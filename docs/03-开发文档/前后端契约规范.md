# 前后端契约规范

> 帮扶管理信息系统 v1.13.0 | 2026-10-18
> 本规范是前后端开发、测试、CI 的共同依据，违反即视为契约破坏。

---

## 1. 响应信封统一

所有 API 端点响应必须为统一信封格式：

```json
{
  "code": 200,
  "success": true,
  "message": "成功",
  "data": { "...": "业务数据" }
}
```

**规则**:

| 类型 | 要求 |
|------|------|
| 数据返回 | 后端用 `success_response(data=...)`（`app/core/response.py`） |
| 列表返回 | 后端用 `ok_list(items, total, page, page_size)` |
| 消息返回 | 后端用 `success_response(message=...)` |
| 错误返回 | 后端用 `error_response(code, message)` / HTTPException |
| 文件返回 | `FileResponse`/`StreamingResponse`，不参与信封 |

**兜底机制**:`app/middleware/camel_to_snake.py` 中间件会对裸 dict JSON 响应自动补全
`code/success/message` 元数据（不改变数据层级）。已含 `success`/`code` 的响应、文件/流式/错误响应跳过。

**禁止**:
- ❌ 返回裸 dict（如 `return {"counts": ...}`）——已由中间件兜底，但新代码必须显式使用信封
- ❌ 手动拼半信封（如 `{"code":200, "data":...}` 缺 `success`）
- ❌ 在 `data` 外暴露业务字段（`data` 是唯一业务载荷）

## 2. 前端消费规则

`frontend/src/api/request.ts` 拦截器行为：
- 信封响应：`data` 内字段提升到响应顶层（`res.total` 等价 `res.data.total`），`code`/`success`/`message` 保留
- 裸 dict 响应：原样返回（中间件补全后带 `code`/`success`）
- 裸 list 响应：数组设为 `res.items`

**前端判断成功**：优先用 `res.success === true` 或 `res.code === 200`，不要依赖字段存在性。

## 3. 字段命名契约

- **后端响应字段命名分两套**（取决于模型继承谁，见 `backend/app/models/base.py`）：
  - 继承 `BaseModel` 的模型：`to_dict()` 经 `dict_keys_to_camel` 输出 **camelCase**（`totalAmount`、`villageId`）
  - 继承裸 `Base` 的模型（帮扶村/项目/学校/经费/用户/组织/审计日志等）：走 `_base_to_dict`，输出 **snake_case**
  - 不少模型**自行覆写** `to_dict` 同时给出两套键以兼容前端
- **前端请求体**：camelCase 由后端中间件自动转 snake_case（`backend/app/middleware/camel_to_snake.py`）
- **前端消费**：**不存在**统一的字段名转换工具。响应拦截器（`frontend/src/api/request.ts`）
  只做两件事：① 拆信封 —— 把 `data` 载荷的键平铺到响应顶层；② 数组放 `items`。
  **不做大小写转换**，因此页面必须按后端实际输出的键名取值（新代码优先 camelCase；存量 snake_case 读取保留，向后兼容）

> ⚠️ **本文档曾经过期**：早期版本写"前端转换工具 `frontend/src/utils/camelize.ts`（`camelizeDeep` / `snakeizeDeep`）"，
> 该文件**从未存在于本仓库**。实际的大小写转换发生在后端中间件与模型 `to_dict` 两侧，前端不做转换。

## 4. 菜单（后端单一源，v2）

> v1.13.0 起前端不再维护菜单副本：`frontend/src/config/menu-config.ts`、`frontend/src/utils/systemMenu.ts`
> 已删除，侧栏、移动端底部导航、权限面板、权限包菜单树全部由后端下发数据驱动。

### 4.1 唯一数据源与接口

- **唯一权威**：`backend/app/api/v1/menus.py` 的 `MENU_SECTIONS`（板块定义）+ `MENU_DEFINITIONS`（扁平条目，含 children/tabs）
- `GET /menus/accessible`：按登录人裁剪后的 v2 结构（`source` 说明来源：`user` / `pack` / `role`）
- `GET /menus/all`：管理员可用的**同结构**全量（不做用户级过滤，含完整 `roles`），供权限面板 / 权限包菜单树
- 响应 `data` 结构：`{ "version": 2, "sections": [...], "flat_keys": [...] }`
- 条目字段：`key` / `label` / `path` / `icon` / `order` / `kind` / `roles`，分组与聚合页另有 `children` / `tabs`
  - `kind = page`：普通页面，必须有 `path`
  - `kind = group`：可折叠分组，必须有 `children`（**不允许** path）
  - `kind = console`：系统管理聚合页，必须有 `path` + `tabs[]`；`tabs[].path` 为旧页面路由（聚合页内嵌组件，同时保留直达）
  - `roles = null` 表示所有角色可见；否则为角色白名单（`normalize_role` 语义）
  - `order`：同级升序稳定排序；`flat_keys`：过滤后可见的全部 key（含 group/console 自身 + children + tabs.key）
  - `section`：所属板块 key；`null` 表示不进 sections（`dashboard` 由前端固定渲染；`legacy: true` 历史兼容 key 无导航出口，仅供权限包 / 历史 `allowed_menus` 校验）

### 4.2 板块顺序（侧栏渲染顺序）

| order | section | 板块 | 说明 |
|---|---|---|---|
| 固定 | — | 工作台 | `dashboard` 固定在侧栏顶部，不在 sections 中 |
| 10 | `business` | 帮扶业务 | 帮扶村/项目/学校、经费管理（group）、结对帮扶、捐赠物资、政策法规、工作移交 |
| 20 | `rural` | 乡村振兴 | 工作首页、工作列表、驻村工作台 |
| 30 | `collab` | 工作协同 | 待办事项、审批管理（group）、工作日历、提醒中心、消息中心 |
| 40 | `report` | 分析汇报 | 汇报大屏、数据分析（group：分析仪表盘/地图可视化/工作分析/成效排名/成效评估/舆情监测）、报表模板、报表导出 |
| 50 | `data` | 数据管理 | 数据概览、导出、导入、数据包与批量导入、数据校验、校验规则、综合数据录入、批量操作、数据上报（group） |
| 90 | `system` | 系统管理 | 6 个 console 聚合页：组织与权限 / 安全与审计 / 运维与监控 / 备份与存储 / 系统设置 / 关于与反馈 |

### 4.3 过滤规则（优先级不变）

优先级：superuser 全量 > `user.allowed_menus` > 启用中权限包 > 角色默认；之后并入 `_PUBLIC_ACCESS_KEYS`（政策法规/数据分析公开 key 保持不变）。新增规则：

- `group` 可见 = 其任一 child 可见；children 裁掉不可见项；children 为空则该 group 不出现
- `console` 可见 = `console.key ∈ allowed` **或** 任一 `tab.key ∈ allowed`；
  tabs 裁剪 = `tab.key ∈ allowed or console.key ∈ allowed`（勾了聚合页 key 视为其全部 Tab 可见；旧权限配置里只有 tab key 的用户也能看到该聚合页）
- `section` 过滤后 items 为空则不出现
- 所有旧 key 保留在定义中（通过 group children / console tabs 承载），权限包与历史 `allowed_menus` 不失效

### 4.4 前端消费与单一源约束

- `stores/menu.ts`：解析 v2（`sections` / `flatKeys`），`fetchMenus()` / `fetchAllMenus()`；
  `canAccessMenu(key)` 语义不变（含 tab key；superuser 旁路不变）；保留旧数组结构降级分支与单测
- `layouts/DefaultLayoutSafe.vue`：侧栏完全数据驱动（工作台固定 → 板块 → page/group/console 三种渲染）+ 收藏/最近访问 + Ctrl+K 菜单搜索；
  **禁止再手写菜单段**
- `components/nav/MenuSearchDialog.vue`：搜索 label/key/path（大小写不敏感子串），上下键 + 回车跳转；空搜索显示收藏 + 最近
- `composables/useRecentMenus.ts` / `useMenuFavorites.ts`：localStorage 键 `nav:recent` / `nav:favorites`，上限 8，损坏数据回退空
- `components/layout/MobileBottomNav.vue`：数据驱动（工作台 + sections 前 3 个入口 + "更多"）
- 权限面板（`MenuVisibilityPanel.vue` / `PermissionPacks.vue`）：用 `/menus/all` 渲染「板块 → 入口 → Tab」三级树，
  勾选值仍为 key 列表（保存协议不变）

### 4.5 CI 门禁（`scripts/check_menu_alignment.py`，规则 A~E）

| 规则 | 内容 |
|---|---|
| A | 后端每个带 path 的条目（含 `tabs[].path`）必须命中前端已注册路由 |
| B | 前端每个 `meta.menuKey` 必须存在于后端 key 集合（含 `tabs[].key`） |
| C | 后端每个 key 必须被前端消费（路由 `meta.menuKey` 命中 / group/console 子项命中 / console tab 对应 path 路由存在） |
| D | 同一条路径不得出现两个菜单入口（全局唯一） |
| E | section key 唯一、section 内 order 单调（允许重复但 WARN） |

退出码语义不变（0 通过 / 1 失败），CI 调用方式不变。

## 5. 角色体系

系统固定 **4 个角色**：

| 角色 | 说明 |
|------|------|
| `super_admin` | 超级管理员（全权限） |
| `admin` | 系统管理员（用户/组织/系统配置） |
| `user` | 普通用户（日常录入与操作） |
| `viewer` | 访客（只读） |

**历史角色归一化**（后端 `normalize_role()` / 前端 `normalizeRole`）：

| 历史值 | 归一化为 |
|--------|---------|
| `manager` | `admin` |
| `approval_leader` | `admin` |
| `operator` | `user` |
| `guest` | `viewer` |

前端禁止新增旧角色字面量；用户列表对历史角色显示归一化后的名称。

## 6. 版本一致性

- **唯一权威来源**：根 `package.json` 的 `version` 字段（后端由同步脚本写入
  `backend/app/core/config.py` → `Settings.PROJECT_VERSION`）
- 全部目标文件（含若干 optional 项）由 `node scripts/sync-version.js --write` 单源同步；
  `node scripts/sync-version.js --check` 为 CI 门禁
- ⚠️ 旧脚本 `scripts/sync_version.py` 只覆盖 6 类文件且无校验能力，仅被构建流水线按 tag 使用，
  不要把它当作唯一同步手段
