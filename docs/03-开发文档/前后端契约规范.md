# 前后端契约规范

> 帮扶管理信息系统 v1.9.0 | 2026-08-16
> 本规范是前后端开发、测试、CI 的共同依据，违反即视为契约破坏。

---

## 1. 响应信封统一

所有 API 端点响应必须为统一信封格式：

```json
{
  "code": 200,
  "success": true,
  "message": "成功",
  "data": { "...": "业务数据" }
}
```

**规则**:

| 类型 | 要求 |
|------|------|
| 数据返回 | 后端用 `success_response(data=...)`（`app/core/response.py`） |
| 列表返回 | 后端用 `ok_list(items, total, page, page_size)` |
| 消息返回 | 后端用 `success_response(message=...)` |
| 错误返回 | 后端用 `error_response(code, message)` / HTTPException |
| 文件返回 | `FileResponse`/`StreamingResponse`，不参与信封 |

**兜底机制**:`app/middleware/camel_to_snake.py` 中间件会对裸 dict JSON 响应自动补全
`code/success/message` 元数据（不改变数据层级）。已含 `success`/`code` 的响应、文件/流式/错误响应跳过。

**禁止**:
- ❌ 返回裸 dict（如 `return {"counts": ...}`）——已由中间件兜底，但新代码必须显式使用信封
- ❌ 手动拼半信封（如 `{"code":200, "data":...}` 缺 `success`）
- ❌ 在 `data` 外暴露业务字段（`data` 是唯一业务载荷）

## 2. 前端消费规则

`frontend/src/api/request.ts` 拦截器行为：
- 信封响应：`data` 内字段提升到响应顶层（`res.total` 等价 `res.data.total`），`code`/`success`/`message` 保留
- 裸 dict 响应：原样返回（中间件补全后带 `code`/`success`）
- 裸 list 响应：数组设为 `res.items`

**前端判断成功**：优先用 `res.success === true` 或 `res.code === 200`，不要依赖字段存在性。

## 3. 字段命名契约

- **后端响应统一 snake_case**（`total_amount`、`village_id`）
- **前端请求体**：camelCase 由中间件自动转 snake_case（`app/middleware/camel_to_snake.py`）
- **前端转换工具**：`frontend/src/utils/camelize.ts`
  - `camelizeDeep(obj)`：响应 data 载荷 snake→camel（信封元数据键 `code/message/success/data/items/total/page/page_size` 不转换）
  - `snakeizeDeep(obj)`：请求体 camel→snake
  - 新代码优先用 camelCase 消费；存量 snake_case 读取保留（向后兼容）

## 4. 菜单对齐

- **唯一数据源**：后端 `app/api/v1/menus.py` 的 `MENU_DEFINITIONS`
- 前端菜单渲染：运行时拉取 `/menus/accessible`（按角色过滤）
- 管理端配置：拉取 `/menus/all` 全量
- 前端 `src/config/menu-config.ts` 仅用于管理面板辅助展示，其 key/path 必须与后端定义一致
- **CI 门禁**：`scripts/check_menu_alignment.py` 校验
  - 前端每个菜单 key 必须存在于后端 MENU_DEFINITIONS
  - 前端每个 path 必须存在于前端路由
  - 已知废弃 key（页面已移除）在白名单中，新增废弃项须同步维护

## 5. 角色体系

系统固定 **4 个角色**：

| 角色 | 说明 |
|------|------|
| `super_admin` | 超级管理员（全权限） |
| `admin` | 系统管理员（用户/组织/系统配置） |
| `user` | 普通用户（日常录入与操作） |
| `viewer` | 访客（只读） |

**历史角色归一化**（后端 `normalize_role()` / 前端 `normalizeRole`）：

| 历史值 | 归一化为 |
|--------|---------|
| `manager` | `admin` |
| `approval_leader` | `admin` |
| `operator` | `user` |
| `guest` | `viewer` |

前端禁止新增旧角色字面量；用户列表对历史角色显示归一化后的名称。

## 6. 版本一致性
